# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**My Space** — a Tauri 2 desktop app intended to aggregate multiple internal/work tools behind a left sidebar, added one feature at a time. Scaffolded with **tauri-ui** (`bun create tauri-ui`, `vite` template + `--starter` dashboard). Stack: Tauri 2 (Rust) + React 19 + TypeScript + Vite + **Tailwind v4** + **shadcn/ui** (built on `@base-ui/react`, not Radix). Package manager is **bun**.

## tauri-ui reference

This project is based on the tauri-ui template. When working on template structure, shadcn/ui conventions, batteries (debug-panel, workflow), or scaffold options, consult the official docs: **https://tauriui.vercel.app/docs**

## Commands

Run from repo root. `bun` and `cargo` must be on PATH (`export PATH="$HOME/.bun/bin:$PATH"`; `source ~/.cargo/env` if `cargo` is missing).

```bash
bun install            # once
bun run tauri dev      # dev mode — opens the app window, hot-reloads (Ctrl+C to quit)
bun run tauri build    # production build → src-tauri/target/release/bundle/ (.dmg + .app)
./bin/install.sh       # 위를 감싼 배포용 래퍼 — PATH·서명키 준비 + .dmg 굽기 (--universal / --install / --help)
./bin/patch-version.sh # 릴리스 한 번 — 버전 올림 → 커밋·태그·푸시 → CI 감시 → 초안 퍼블리시 (--minor / --dry-run / --help)
bun run build          # frontend only: tsc -b + vite build (the type-safety gate)
bun run typecheck      # tsc --noEmit
bun run lint           # eslint
bun run format         # prettier --write
```

There is no test runner. `bun run build` (via `tsc -b`) is the type gate. First `cargo` compile is slow (~2 min, plus a few more for `rdkafka` — it builds bundled librdkafka from C source); later builds are incremental. Rust-only check: `cd src-tauri && cargo check`.

## Architecture

**Single window, Slack-style shell + menu-registry view switching (no router lib).** The UI mirrors the current Slack desktop app. `src/App.tsx` composes the shell from `src/components/shell/`, on a `bg-ui-chrome` root: `<TitleBar>` (40 px `bg-ui-chrome`, macOS Overlay title bar → 78 px left gap for the traffic lights, whole bar is `data-tauri-drag-region` except the three centred pills, which are **내 일정 · 구성원 일정 빠른 검색 · 회의실 예약** in that order. Each is a fixed **150 px** pill — the search one used to be `flex-1` inside a `w-[min(680px,58%)]` row and ate half the title bar for a control whose real input lives in the dropdown anyway, so the row is now content-width and every pill states its own width. **내 일정** (`MySchedulePalette`, `my-schedule-palette.tsx`) is the leftmost: it opens the primary calendar's 이번주·다음주 (`gcal_upcoming`) in the same `WeekSection` the 캘린더 뷰 uses. It deliberately does **not** use `useGcal()` — that hook gates its 5-minute poll on `useTabActive()`, which is always `true` in the always-mounted title bar, so it would call every 5 minutes for as long as the app is up; like the 회의실 예약 palette it loads on open only, with an explicit ↻ as the sole refresh. Its dropdown is left-aligned to its own pill (centring or right-aligning would push the leftmost dropdown off-window when the window is narrow). Then the **구성원 일정 빠른 검색** — `EmployeeSearchPalette` (`src/features/gcal/employee-search-palette.tsx`), a title-bar dropdown that searches the domain directory and shows one member's 이번주·다음주 일정 inline, reusing the gcal backend (`gcal_people` + `gcal_person_events`); it works even when the sidebar is collapsed. **회의실 예약** (`RoomBookingPalette`, `room-booking-palette.tsx`) sits at the right end of the same centred row: open it and it lists every saved room with 예약 가능 / N시까지 사용 중 for the chosen slot (defaults to the next full hour + 1 h, recomputed on each open — a tray app left open overnight would otherwise answer "지금 빈 방" with yesterday's clock), 예약 가능 first, and books straight through `gcal_book_room`. Three rules it must keep: it **reads** `myspace.gcalRooms` with `readSavedRooms()` rather than `useLocalStorage` (two hooks on one key in the same window never see each other's writes, so it would fight the 회의실 tab for the list) and falls back to auto-suggesting known rooms from `gcal_calendars` **without saving them**; it carries **no polling** — the title bar is always mounted, so `useTabActive()` can't gate it and a periodic refresh would call once per room forever, hence load-on-open only; and because `gcal_calendar_events` only covers 오늘~다음주 일요일 (`upcomingRange()`, mirroring Rust's `upcoming_range()`), a date outside that window reports 가용 여부 확인 불가 instead of an empty — i.e. falsely free — room. The old "My Space 검색" menu-filter — the pill, the ActivityBar "메뉴 검색" container, and the SideBar search input — was removed) → row of `<ActivityBar>` (64 px rail, icon above an 11 px label; **container icons are gone** — "탐색기" was the last one and a one-item picker picks nothing, so the rail now holds only pinned menu shortcuts, with the theme toggle + 설정 at the bottom, and collapsing the sidebar is the title bar's toggle) + `<SideBar>` (white panel, `rounded-tl-[var(--ui-panel-radius)]`, resizable via `myspace.sidebarWidth`) + editor area (`<TabBar>` = underline tabs + an 18 px bold view header, then the active view at `p-5`) → `<StatusBar>` (26 px, chrome-coloured). `src/main.tsx` wraps everything in `ThemeProviders` (preset + light/dark) and `ExternalLinkGuard`.

**Open views are tabs.** `src/lib/use-open-tabs.ts` owns `openIds` (localStorage `myspace.openTabs`) and `activeId` (`myspace.activeMenu`), and exports `SETTINGS_ID`. Closing the active tab activates the right neighbour, else the left; the last tab can't be closed. `move(draggedId, targetId, before)` reorders `openIds` (tab drag & drop). `src/components/shell/tab-bar.tsx` keeps tabs at a fixed width (`shrink-0`, 112–240 px, so names never get squeezed), scrolls the row when it overflows, and then shows an IntelliJ-style `⌄` list button (with the count of off-screen tabs) that opens every open tab in a dropdown.

**Tabs are keep-alive.** A tab's view mounts the first time it's activated and stays mounted until the tab is closed — going back to a tab must show the *previous* data, not re-fetch. Inactive tabs are stacked `absolute inset-0` and hidden with `invisible` (not `hidden`/`display:none`, which would reset their scroll position). Consequences to respect: (1) nothing may rely on unmount for cleanup on tab switch — use `useTabActive()` (`src/lib/use-tab-active.ts`, supplied by `TabActiveProvider` in `src/lib/tab-active-store.tsx`, `true` when there is no provider, e.g. the pet window) instead; (2) **periodic refresh must be gated on `useTabActive()`**, otherwise every open tab polls at once — `use-gcal.ts` / `use-jira.ts` show the shape: one effect does the initial load, a *separate* effect owns the `setInterval` and depends on `tabActive` (merging them would re-fetch on every tab switch, which is exactly what keep-alive avoids); (3) native child webviews are drawn *over* the window and ignore CSS, so **every view that embeds one** (`browser`, `cowork-ai`, `claude-design` — anything using `useWebviewBounds`) must call `browser_hide` when `tabActive` goes false and re-show via `browser_open` when it comes back, otherwise the embedded page stays on top of whatever tab you switch to.

**Browser memory: kill the `WebContent` process, never close the webview.** **One browser tab = one WKWebView = one `WebContent` process = 200–400MB**, so two tabs cost 600MB and hiding reclaims none of it. Everything that looks like it should free that memory was measured and **does not**: navigating to `about:blank`, `location.replace('about:blank')` (no bfcache entry left), and even releasing the WKWebView outright (`removeFromSuperview` + nil) all leave RSS at ~370MB with the process alive — WebKit holds `WebContent` in its process cache and that process never returns memory to the OS. The one thing that works is `kill_web_content()` in `lib.rs`: read the renderer's pid off the WKWebView with `_webProcessIdentifier` and `SIGKILL` it from a spawned thread. The process exits, returning every byte; WebKit immediately replaces it with an empty renderer (~56MB) and reloading the URL brings the tab back normally (measured: pid confirmed dead, replacement renderer 56MB). It is private API, so the pid is read behind a `respondsToSelector:` check — if a future macOS drops it, memory just stops being reclaimed and nothing breaks. **Killing the process is only half of it: without `with_process_terminate_hook()` Tauri puts the page straight back.** `tauri-runtime-wry` installs a default `on_web_content_process_terminate` handler whose whole body is `webview.reload()` (`tauri-runtime-wry-2.11.4/src/lib.rs:5133`), so every kill was measured being undone in the same second — `WebContent 프로세스 종료 pid=61772` followed by wry's `webview reloaded` and a fresh load of the tab's URL, RSS right back where it started. That is why `run()` starts with `with_process_terminate_hook(tauri::Builder::default())`: the app-level hook replaces the default (`prepare_webview` only fills in `pending.on_web_content_process_terminate_handler` when one is set, and wry skips its default branch when that field is `Some` — child webviews built by `add_child` go through the same path). It skips the reload for labels in `killed_labels()` and reloads everything else, so a genuine renderer crash still recovers exactly as before. `kill_web_content` must insert that label **before** sending `SIGKILL`, or the hook wins the race and revives the page. Measured after the fix: the daum.net tab's renderer (516MB) exited and *no* replacement renderer appeared at all. **Do not "fix" this back to `_killWebContentProcessAndResetState`. That selector does not work on macOS 26 (Darwin 25) and three ways of sending it were measured failing:** sent directly it returns with `respondsToSelector:` = `true` and the process stays alive (RSS unchanged, no wry "web content process terminated"); deferred with `performSelector:withObject:afterDelay:0` it is never even executed, because that API puts a timer on *the calling thread's* run loop and `kill_web_content` runs on a Tauri command thread that has no run loop; handed to the GCD main queue with `dispatch_async_f` the block does not run either. Reading a pid is a plain getter — no nested run loop, so none of the deadlock hazards that shaped the old code apply. `browser_close` still splits its work across ticks (hide now, kill, `close()` on a 1 s delayed thread) because webview teardown is asynchronous and the tab must leave the screen immediately. Closing the webview is a trap on top of all this: **wry 0.55 deliberately leaks it** — `impl Drop for InnerWebView` (`wkwebview/mod.rs:1396`) calls `removeFromSuperview()` then `self.webview.retain()`, putting the refcount back, so the object is never deallocated while Tauri's registry forgets it, and reopening the tab builds a *second* webview (wry 0.54.2 does the same; bumping the version does not fix it). So `browser_discard` hides the webview, kills its process, and records the label in `discarded_labels()`; `browser_open` sees the label there and re-navigates to the tab's stored URL, which is why the frontend never tracks what was discarded. `browser_close` exists only for the tab's own X button (that label is a tab id and never returns) and kills the process *before* closing, so the shell that wry leaks leaks empty. One more consequence: killing the process resets the webview to `about:blank`, so `on_page_load` must **not** emit `browser:navigated` for that URL — the frontend would overwrite the tab's stored address with `about:blank` and lose where it was (`use-browser.ts` also repairs tabs already poisoned that way).

Two supporting pieces. `browser_hide` sends `setHidden:YES` to the native WKWebView (`set_webview_hidden`, same `with_webview` + `msg_send!` route as the back/forward gestures) *and* keeps the old move-off-screen as the non-macOS fallback; a merely off-screen view is still on-screen as far as WebKit is concerned and keeps its backing store, GPU resources and full-speed timers. And `browser-view.tsx` empties tabs nobody has looked at for `settings.browser.discardMinutes` (설정 → 브라우저; default 5, 0 = never), dimming them in the tab strip. Four rules that timer keeps: it is the **one periodic job that must NOT be gated on `useTabActive()`** — being away from the browser is exactly when reclaiming matters; **"not looking" includes the window not being focused**, so the watched-tab decision is `visible && windowFocused` (`getCurrentWindow().onFocusChanged`) — `useTabActive()` alone only covers switching to another *menu* tab, and this is a tray-resident app whose browser tab sits active while you work in another app, which measured as the clock being rewound forever and the page never being reclaimed; that focus flag must stay **out of `visible`**, which decides whether the native webview is drawn — mixing it in makes the page vanish every time you click another app; the tab being watched has its clock rewound every tick via a ref, not an effect dependency (a dependency would reset the interval on every tab switch, so it would never fire); and closing the browser menu tab empties **every** tab immediately, since the tab list survives in localStorage and reopening only reloads the active one. A fifth rule falls out of killing the reload: **reviving a discarded tab is its own effect.** The tab that gets reclaimed most is the *active* one — browser menu tab open, you working in another app — and the only thing that changes when you come back is `windowFocused`, which the placement effect deliberately does not depend on, so nothing would reopen it and you'd return to a blank page (wry's auto-reload used to hide this). Adding `windowFocused` to the placement effect is the wrong fix: it also runs when focus is *lost*, calling `browser_open` on the tab that was just reclaimed and undoing the reclaim. So a separate effect opens the active tab only when it is both watched (`visible && windowFocused`) and actually dead (`!liveRef.current.has(activeId)`) — it no-ops otherwise, and the tab strip's "해제됨" dimming is cleared on the same condition so the indicator and the reality can't disagree.

**A link that asks for a new window opens in Chrome, not in a new app tab.** `target="_blank"` / `window.open` inside a browser tab goes to `open_in_chrome_window` (`lib.rs`) — those links are almost always something to *look at* (an attachment preview, an external doc, a payment page), and an in-app tab would cost another `WebContent` process (200–400MB, see above). Three things this forces. **The URL reaches Rust over a custom scheme, and it must be a top-level navigation, not a hidden iframe.** `NEW_TAB_SCRIPT` (injected into every tab webview, because Tauri IPC is not available on external origins) intercepts the click and sets `location.href = "tauri-newtab://open/?url=…"`; the plugin's `on_navigation` picks the scheme up and returns `false`, so the page the user was on stays exactly where it was (a cancelled navigation never fires `beforeunload`). The original iframe carrier is what made this **look like nothing was wired up at all** — a site's CSP (`frame-src`/`default-src`) blocks the frame silently, and most large portals have one, so the click did nothing and left no trace. **`on_new_window` stays as the native fallback** for requests the script didn't intercept; the two can't double-fire because an intercepted click is `preventDefault`ed and the overridden `window.open` never reaches WebKit. **And macOS needs `open -na … --args --new-window`**: without `-n`, `open -a` on a running Chrome drops `--args` entirely and the URL lands as a *tab* in whatever window is in front (measured: `-n` took the window count 11 → 12, plain `-a` left it at 11). Chrome missing ⇒ `open` exits non-zero ⇒ fall back to the default browser, because a link that opens nowhere is the worst outcome.

**Any view can be popped out into its own window.** The view header's right-hand `↗` button calls the Rust command `open_view_window(id, title)`, which creates (or focuses) a window labelled `view-<menu id>` pointing at `index.html?view=<menu id>`; the tab stays open, so window and tab can sit side by side. `src/lib/window-role.ts` is the single source of truth for "which window am I" (`WINDOW_LABEL`, `isMainWindow`, `isViewWindow`, `viewWindowMenuId()`), `src/main.tsx` routes `view-*` to `ViewWindowRoot` (`src/features/popout/`), which wraps the same providers as `App.tsx` and renders one view — no tabs, so `useTabActive()` is always `true` and polling just works. `src/lib/view-info.tsx` (`viewInfo` / `viewElement`) maps an id → title/icon/group and element for the tab bar, `App.tsx`, and the pop-out window alike. Three things multi-window forces on you: (1) **global schedulers must be gated on `isMainWindow`** — `reminder-store.tsx` and `claude-activity-store.tsx` do, or a pop-out would fire every reminder twice and double-log activity; (2) `useLocalStorage` syncs across windows via the `storage` event (without it each window's stale snapshot would overwrite the other's writes); (3) native child webviews attach to the **calling** window (`browser_open` / `github_import_chrome_cookies` take `tauri::Window`) and their labels must come from `browserLabel()` so main and pop-out don't fight over one webview. New windows need their label glob in `src-tauri/capabilities/default.json` (`view-*`).

**Launch at login is on by default, and launches *silently*.** `settings.general.autoStart` (설정 → 일반, default **true** — the app is a tray resident whose whole point is watching for work, so off would make it pointless) is only the *intent*; the OS registration is `tauri-plugin-autostart` with `MacosLauncher::LaunchAgent` (a `~/Library/LaunchAgents` plist — the AppleScript launcher would prompt for "System Events" automation permission). `src/features/settings/use-autostart.ts` reconciles the two: `useAutoStartSync()` (mounted once in `App.tsx` as `AutoStartSync`, inside `SettingsProvider`) applies the setting on startup and on change, and the panel also awaits `applyAutoStart` so it can re-read and display the *real* registration state — registration can fail silently. Two things this forces: (1) **dev builds don't register** (`AUTOSTART_SUPPORTED` is false when `import.meta.env.DEV`), because the registered binary would be `src-tauri/target/debug/…` and cleaning the target dir would leave a broken login item behind; the panel says so instead of looking broken. (2) The plist launches the binary with `--autostart` (`AUTOSTART_FLAG` in `lib.rs`, which must stay in sync with the plugin's args), and `on_page_load` **skips `show()` for `main`** when `launched_at_login()` — so a login start puts the app in the menu bar with no window, while a manual launch behaves normally. The webview still loads (hidden), so herdr watching, notifications, and the pet all run; the tray's "My Space 열기" (`present_main`) brings the window out.

**Desktop pet (`pet` window)** — the character, and **the app's only notification surface**. There used to be a second window, `widget`, a popover anchored under the tray icon that showed reminders and Claude Code notices; the pet already showed the same things in its bubble, so the popover was deleted (one window fewer = one WebContent process fewer — see `src-tauri/src/pet.rs`'s header). 상시 표시 is off by default, toggled from 설정 → 데스크톱 펫 (`settings.pet`: `enabled` / `bubble` / `clickThrough` / `scale` / `notify`) or from the tray menu's 펫 표시/숨기기 (which can't flip localStorage from Rust, so `pet::request_toggle` emits `pet:toggle` and `PetController` does it). **Visibility is the OR of two axes**: `settings.pet.enabled`, and Rust's `pet:alert` — otherwise turning the pet off would silently swallow every reminder. `PetAlert` (`pet.rs`) holds that second axis **per source** (`AlertSource::Herdr` / `Reminder` / `App`); collapsing it to one bool means dismissing a reminder also clears the herdr alert, which the watcher loop then re-sets a tick later, and the pet blinks. Rust owns the signal rather than the pet because a hidden window's webview isn't loaded, so the pet can't notice it has something to say; it computes nothing about *size*, though — `PetController` (`src/features/pet/pet-controller.tsx`, mounted once in `App.tsx`, gated on `isMainWindow`) is what calls `pet_show` / `pet_hide`, because `petWindowSize()` / `readPetAnchor()` live there. `src/main.tsx` routes the `pet` label to `PetRoot` wrapped in `SettingsProvider` so the pet reads the same live settings. `src-tauri/src/pet.rs` owns the window: transparent, `alwaysOnTop`, `visibleOnAllWorkspaces`, `focus: false`. Three things it forces: (1) **the window is sized to its content, not the reverse** — transparent pixels still swallow clicks, so `PetRoot` measures itself with a `ResizeObserver` and calls `pet_resize`, which pins the **bottom centre** so a growing speech bubble doesn't shift the character. Two windows compute that size, which is where it goes wrong: `pet-metrics.ts` is the single source of truth (`PET_BASE`, `PET_PAD`, `petWindowSize()`), the controller passes `petWindowSize(scale)` — the **padded** size, not the character size — to `pet_show`, and `PetRoot` takes its padding from the same `PET_PAD` as inline style rather than Tailwind classes. Get that wrong and the first show clips the top of the character. Re-showing needs `pet_show`'s `pet:shown` event too: the content size hasn't changed, so the `ResizeObserver` stays silent and the window would keep whatever `pet_show` guessed; (2) for the same reason the saved position (`myspace.petAnchor`, `pet-anchor.ts`) is a bottom-centre anchor, not a top-left origin — the pet window writes it on `onMoved`, the controller reads it when showing; (3) the pet gets its state purely from the `herdr:*` / `reminder:*` events Rust already broadcasts with `app.emit` (`use-pet-mood.ts`), so it adds **no** polling of its own — and shows nothing new when 작업 감시 is off, because then no events are emitted. **`PetMood` is the behaviour spec, four states only** (`use-pet-mood.ts` is the source of truth; the settings panel's table mirrors it): `idle` = nothing running and nothing to confirm → *asleep* (closed eyes + a `Zzz` badge); `running` = one Claude task working; `busy` = two or more working (badge shows the count); `waiting` = something needs the user (task finished, AskUserQuestion, a fired reminder, or an app notice — new mail / Slack message / upcoming event). Priority is `waiting > busy > running > idle` — anything needing a human wins regardless of how many tasks are running. "Running" is counted per **herdr workspace**, not per herdr session, since one session can hold several tasks. Reminders are not a separate pose: they map to `waiting` and differ only in the badge, keyed off `PetNotice.kind` (never off the chip's text — that silently breaks when wording changes). The Petdex sheet has no sleeping row, so sprite species use its `idle` row and rely on the `Zzz` badge to say "asleep" — no species closes its eyes any more, so the badge is the only cue and the 설정 behaviour table is worded that way.

**Three interactions, three owners.** Dragging moves the window. Clicking the *character* toggles a **speed dial** — a column of menu icons that fans upward, each carrying an unread badge; picking one calls `pet_open_menu`, which shows the main window and emits `pet:open-menu`, and `App.tsx` turns that into `open(id)` (the tab state in `useOpenTabs` exists only in the main window, so the pet cannot open a tab itself). Clicking the *head badge* toggles a panel of **in-flight Claude tasks only** — `PetState.tasks`, whose `detail` is the **user's prompt**, since that is the answer to "what is it doing?". The two overlays are mutually exclusive: both stack above the character, and showing them together makes the window cover the screen. Running tasks never surface on their own — a bubble that stays up until a task finishes is just noise, so it is click-to-reveal. Keep unread counts out of that panel: they belong on the dial badges, and mixing two kinds of information into one list makes it unclear what you are looking at.

**Unread counts come from the main window, not from the pet.** `PetFeedPublisher` (mounted in `App.tsx`, gated on `isMainWindow`) reads the `SlackProvider`/`GmailProvider` state that is *already* polling and hands `{menuId, count}` records to Rust via `pet_set_feed`; Rust keeps them in `PetFeed` state and emits `pet:feed`, and the pet window subscribes plus queries `pet_feed` once on mount (`usePetFeedCounts`). **Do not "simplify" this back to localStorage + the `storage` event**: that path depends on window start order — if the pet webview loads before the first poll it reads an empty value and never sees the update, so the badges sit at 0 forever. The Rust-mediated path is the same one the herdr notices use, which is how the pet's mood already works. Mounting those providers in the pet window instead would double every poll and duplicate the connection state. Slack's count follows `slack-menu-badge` exactly, or the sidebar and the pet quote different numbers. **Gmail deliberately does not**: a dial icon has room for *one* badge, while `gmail-menu-badge` shows two (red = 관심, grey = all unread), so the dial takes the 관심 count only — falling back to all-unread would hang a three-digit number off the icon, which reads as noise rather than "look at this now". No 관심 filter configured (설정 → Gmail) ⇒ no Gmail dial badge. Dial icons and titles come from `MENUS` (`pet-dial-items.ts`) rather than being redeclared, so renaming a menu can't desync them.

**Which notifications the bubble carries is a setting, and it starts at Claude-only.** `settings.pet.notify` (설정 → 데스크톱 펫 → 받을 알림) has five sources: `claude` and `reminder` (생산성 → 알림 메뉴의 리마인더) default **on** — those two predate the setting, so the defaults *are* the old behaviour — while `gmail`, `slack`, and `gcal` default **off**, because a tray resident that announces every mail is noise. Google 캘린더 is the one source split into **parent + when**: `gcal` decides *whether* to notify, `gcalStart` / `gcalBefore` (both default on, but dead while the parent is off) decide *when* — the publisher gets `gcal && gcalStart` / `gcal && gcalBefore`. Two switches instead of three would mean turning the calendar off erases which timings you picked, so re-enabling costs two more clicks; the UI indents the two under the parent and dims them rather than hiding them (hidden controls read as "not supported"), and warns when the parent is on with neither timing chosen — that combination is silently inert. **Each source is muted at a different layer, and that is not an accident — it's where the notice is born.** `reminder` is cut off at the *scheduler*: `reminder-store.tsx` reads the setting and simply doesn't call `reminder_fire` (it still stamps `firedAt`/`lastFired`, so re-enabling doesn't dump every missed reminder at once, and it calls `reminder_dismiss` when you switch it off so an on-screen reminder doesn't outlive the setting and pin the pet open). Three paths, and the split is the whole point: **herdr notices are made by Rust**, so muting them frontend-only would leave the pet popping up over an empty bubble — `PetController` therefore pushes the flag down with `pet_set_claude_alert`, and `pet.rs`'s `AlertState` keeps `claude_muted` next to the per-source `active` array so `any()` ignores a muted source (and re-emits `pet:alert` the moment you toggle it, or the pet stays on screen looking un-muted). `usePetMood` *also* filters them, because a permanently-visible pet keeps receiving `herdr:*` events regardless of the alert axis. That filter cuts notice cards only — mood, `running`, and the task panel still animate while Claude works, since this is an "알림" switch, not a "stop watching" switch (that one is 작업 감시). **Gmail/Slack/캘린더 notices are made by the main window** and relayed through Rust exactly like the dial counts: `PetNotifyPublisher` (`pet-notify-publisher.tsx`, mounted in `App.tsx` inside the providers, gated on `isMainWindow`) calls `pet_notify`, Rust holds them in `AppNotices`, emits `pet:notices`, and the pet window subscribes + queries `pet_notices` once on mount (`useAppNotices` in `pet-notify.ts`) so a webview that cold-loads late still fills in. Four rules that publisher must keep or it turns into a spam machine: (0) **a notice whose cause is gone is withdrawn, not just left to expire** — read the Slack message in Slack and the pet must stop announcing it, or with 항상 표시 (TTL 0) the bubble contradicts reality. `liveRef` (id → 채널·ts, separate from `seenRef`, which must survive dismissal so nothing is re-announced) is walked on every poll and anything no longer unread is `pet_dismiss_notice`d. Two traps: the unread list is **truncated** when there's a lot of it (`has_more`), and what gets cut is always the *oldest*, so "absent from the list" alone would silently delete unread notices — `stillUnread()` only calls it read when the ts is **inside the fetched range** (newer than the oldest message still listed), and defers otherwise; and a failed poll (`error`) keeps the previous `channels`, so the sweep is skipped that cycle. Silently erasing an unread notice is worse than leaving a stale one up, which is the tie-breaker for every judgement here; (1) **the first snapshot is seeded, not announced** — otherwise every already-unread mail fires the moment the app starts (and again whenever you re-enable the switch, which is why `useSeenIds` clears on `enabled: false`); (2) **ids are stable per source item** (`gmail:<id>`, `slack:<channel>:<ts>`, `gcal:before|start:<epoch>:<title>`) because polling hands back the same list every cycle; (3) **batches are capped** (`MAX_PER_BATCH` = 3) since the bubble only expands 2 cards anyway — don't cut it below the visible count, or the surplus vanishes without even reaching the "N개 더 보기" row. Gmail follows the badge's priority — 관심 filter if 설정 → Gmail has one, else all unread. **Where a card takes you is itself a setting, for the two sources that have somewhere else to go** — `claudeTarget` and `slackTarget` (`PetNotifyTarget` = `"myspace" | "app"`, each indented under its own row in 받을 알림). Both default to what that notice's subject *already lives in*, which is also the pre-setting behaviour: Claude → `app` = the terminal the task runs in (`herdr_focus_workspace`), Slack → `myspace` = the Slack menu tab. The other value is the escape hatch: Claude's `myspace` opens the 세션 목록 (`pet_open_menu`, for reading the log without a terminal window jumping to the front — this is a tray app), Slack's `app` opens the message itself through the same `slack_open_message` deep link the Slack view uses (a message is usually something you *reply* to). Three rules hold it together: the Slack notice **carries the original coordinates** (`AppNotice.link` = `{kind, channel, ts, threadTs}`, mirrored in `pet.rs`) rather than having the pet re-split its `slack:<channel>:<ts>` id — the maker and the reader assembling the same string separately is how they silently drift, and `threadTs` isn't in the id at all; the choice is read **at click time** inside `usePetMood`, not baked in when the notice is made, because a 항상 표시 card can sit there long after you changed the setting; and `claudeTarget` also governs the **진행 중 작업 rows** in the head panel, since two lists in one window sending the same click to different places is exactly what makes a UI unpredictable. The calendar arm is the one place with **its own poll** (`gcal_today` every 5 min + a 30 s due-check): `useGcal()`'s refresh is gated on `useTabActive()`, so events would go stale whenever the 캘린더 tab is closed — which is most of the time for a tray app. It skips all-day events (no start time to count back from) and only fires 정시 inside a 2-minute grace window, or launching the app in the evening would replay the whole day. TTL is owned by whoever *created* the notice: `notifyPet` schedules its own `pet_dismiss_notice` after `noticeSeconds` (0 = 항상 표시 keeps it until clicked), the same "frontend schedules, Rust relays" shape as `reminder.rs` — don't move a timer into Rust for this.

`usePetMood()` returns `{ mood, running, notices, tasks }`: the bubble stacks pending notifications (up to `MAX_VISIBLE` = 2, then an "N개 더 보기" row that opens the main window), because collapsing them all into one loses which task each is about while stacking them all makes the window — which is sized to its content — cover the screen and swallow clicks meant for the app behind it; `mood` comes from the first entry. Each row is built like a 작업목록 card — source icon (Claude logo for herdr, the service's brand logo for Gmail/Slack/캘린더, bell for reminders) + status chip + bold task name + muted prompt/recap — and the chip text/colour comes from `statusInfo()` in `agent-status.ts` so the pet and the task list never disagree. Task names come from the `herdr:workspaces` snapshot, **not** from `HerdrNotice`, whose `blocked` entries expire after 7 s while the wait itself lasts until answered. A notice may also carry `actions` — a button row under the card, which only reminders use (다시 알림 5분/30분/1시간 + 확인, the popover's controls moved verbatim). They are buttons rather than a card click because a single click can't distinguish 확인 from 5분 뒤 다시; the card click itself opens the 알림 menu. That row is a sibling of the card's body button, not nested inside it, and the card can't use `overflow-hidden` (it would clip the bubble tail), so the body carries matching `rounded-t`/`rounded-b` instead. Each card also carries an **X at its top right** (`dismiss`, another overlaid sibling — buttons can't nest — with `pr-7` on the body so the status chip doesn't slide under it), and what "dismiss" means differs per source, which is why it's a callback rather than one shared handler: a reminder does the real 확인 (`reminder_dismiss`, or the pet stays up on a live reminder), a 완료 알림 clears the Rust `Notices` entry too, but an **입력 대기 can't be cleared at all** — it lasts until answered in the terminal — so those are hidden locally by id. That hidden set is pruned **in the `herdr:questions` / `herdr:workspaces` listeners** (not in an effect — `react-hooks/set-state-in-effect` forbids it), using the same `questionId()` / `blockedId()` helpers that built them: skip the pruning and the same pane's *next* question reuses the id and never shows. Dismissing the last notice also drops `mood` back to `moodOf(running)` — a waiting pose with no bubble says nothing. **A 완료 알림 is only true while that task is still finished**, so `pruneStaleDones` (called from the same `herdr:workspaces` listener) withdraws it — from `dones` *and* from Rust's `Notices` — as soon as the workspace reads `working` (it was given more work) or `blocked` (the user went to the terminal and Claude is now waiting on them). Hiding the card alone is not enough: done notices never expire, so the leftover Rust entry keeps the pet on screen under 항상 표시 and resurrects the card the moment the status returns to done/idle. Only those two statuses count — treating every non-done value as stale would make a newly added backend status silently swallow notices — and `idle` must never be one of them, since `working → idle` is exactly the transition that *creates* the notice. **The other way a Claude notice dies is the user reading it in the terminal without touching the card, and that judgement lives in Rust because the frontend has no signal for it**: herdr reports a finished task as plain `idle` (its statuses are idle/working/blocked/unknown — `done` only ever comes from cmux/Orca), so "I went and looked" changes *nothing* the frontend can see, and under 항상 표시 the card would sit there forever. `mark_seen` (`herdr.rs`) therefore stamps each workspace with `seen` = **터미널 안에서 focused × 그 터미널 앱이 OS 최전면**, and `withdraw_seen_notices` drops every `Notices` entry whose workspace is `seen` (the pet's `dones` follows because the `herdr:notices` listener already discards entries missing from the Rust list). Both halves of that product are load-bearing: `focused` alone makes "terminal left on that pane while I work in Chrome" read as watching, so the notice would be withdrawn before it was ever seen; frontmost alone can't tell which workspace you're looking at. The terminal app is `detect_terminal_bundle()` (process ancestry, 30 s cache) versus `lsappinfo front` — bundle names, not `LSDisplayName`, because they disagree (iTerm.app → "iTerm2") — and `lsappinfo` is used over AppleScript since it needs no Accessibility permission. Two consequences: candidates are limited to `focused && agent_status != "working"`, which keeps the two `lsappinfo` spawns out of the common case *and* — more importantly — makes `seen` known **before** `ClaudeNotifier` sees the transition, so watching a task finish creates no notice at all instead of one that flashes for a tick and is withdrawn; and Orca gets none of this, since it can't report `focused`. The same `seen` flag suppresses 입력 대기 cards (both the `herdr:questions` list, filtered in the watcher, and the live `blocked` card in `pickState`) — leaving the terminal without answering brings them straight back, because blocked is only truly resolved by answering. A workspace that has *vanished* from the list counts as checked too (you closed the tab), but only when another workspace of the **same backend** is present — the per-backend lists fail independently, so without that guard one failed herdr call would erase every herdr notice. 진행 중 작업 rows pass `dismiss: null`: they were opened by a click, so the panel closes the same way. **Species are a registry, and every one of them is now other people's artwork.** `src/features/pet/pet-species.ts` (data only — a `.tsx` exporting non-components breaks fast refresh) lists each species with just an id, a name, and a picker category. The hand-drawn SVG bodies (cat/dog/penguin/robot/alien/ghost) are **gone** — `pet-species-art.tsx`, the `face` eye coordinates, the `Eyes` component, and their `.pet-tail` / `.pet-antenna` / `.pet-lid` CSS were deleted because sitting next to spritesheet characters they read as broken, not as a style. Don't reintroduce a hand-drawn fallback; `petArt()` in `pet-sprite.ts` is the single decision of *what to draw* (sheet vs image, plus the aspect), and an imported kind with no source configured falls back to `DEFAULT_SPECIES`'s bundled sheet rather than to a drawing. Both windows call it — the pet window to render, `PetController` to size the window — because the two disagreeing on aspect is exactly how the first show clips the character. Species are therefore three shapes only: a spritesheet (bundled or `petdex` folder), an animated image per motion (`anim`), or one still image (`custom`); mood expression belongs to the artwork plus `MoodMark`, never to us. Thirteen Petdex spritesheets are bundled into the app (`BUILTIN_SPRITE_IDS` in `pet-species.ts` — data only — paired with `BUILTIN_SHEETS` in `pet-sprite.ts`, which imports the `.webp` files from `src/assets/pets/`; `Record<BuiltinSpriteId, …>` makes the two lists fail to compile if they drift, and that folder's README holds the provenance). They form the 내장 애니메이션 category, so a fresh install animates with no `npx petdex install` and nothing stored in settings, and `DEFAULT_SPECIES` is one of them. They share the whole sprite path with `petdex` — `builtinSource(id)` vs `packageSource(dir)` is the only difference, and their aspect is the spec's `SPRITE_ASPECT` rather than the measured `petdexAspect`. The same 내장 애니메이션 row also lists whatever `pet_list_packages` finds in `~/.petdex/pets` (bundled slugs filtered out, so nothing appears twice); those tiles still store `species: "petdex"` + `petdexDir`, and the 가져오기 `Petdex 폴더` tile counts as active only when `petdexDir` is *not* one of them, or two tiles light up at once. `withDefaults` migrates a stored `petdex` folder whose basename is a bundled id over to the built-in — same artwork, one less thing that breaks when the folder is deleted. All thirteen are other people's artwork with no license field in `pet.json`, so **redistribution is still unresolved** now that the repo is public — see `src/assets/pets/README.md`. **The `.webp` filename must equal the petdex slug** (hence `mini-jerry` / `pinkribbonchibi`, not their `pet.json` `displayName`), because that migration compares a folder *basename*. Two (`mini-elon` / `steve-jobs`) were bundled until 2026-07-30 and were **removed before the first public release** because they are likenesses of real people; don't add them or any other real-person character back. `luffy` is a One Piece character and thus other-company IP — bundled 2026-07-31 by the owner's explicit call, over that objection; treat it as the exception to remove first if a rights holder asks, not as licence to bundle more third-party characters. Dropping a sheet is just its `.webp` plus its `BUILTIN_SPRITE_IDS` / `BUILTIN_SHEETS` / `PET_SPECIES` entries — `migratePet` in `settings-context.ts` resets a setting that still names a species that no longer exists, otherwise the pet renders an empty window. The imported kinds below cover anything the bundled thirteen don't:

- **`anim`** plays one animated image **per motion** (`animPaths` in settings, `pet-anim.ts`): GIF / APNG / animated WebP, which the webview plays by itself in an `<img>` — no frame grid, no state table, no timer. This is the low-friction alternative to petdex: any character GIF works. Only **paths** are stored (animated files run to several MB, and four of them as data URLs would blow the localStorage budget), so the pet window reads them on demand via `pet_read_anim` with a module-level cache; the trade-off is that moving the source file breaks it. A missing slot falls back to `idle`, then to any filled slot, then to the built-in cat, so one file is enough to start. Frames are letterboxed into a square box with `object-contain` — deliberately, so arbitrary aspect ratios never resize the window.
- **`custom`** renders a user-supplied image: `pet_read_image` returns a ≤512 KB data URL stored **in settings** rather than as a path, so the pet survives the original file moving and no window re-reads it. No facial expression, so mood shows only through movement and the head badge.
- **`petdex`** plays a [Codex pet package](https://petdex.dev) — `pet.json` + a spritesheet that is an **8×9 grid**, one row per animation state. `pet_list_packages` scans `~/.petdex/pets/*` (where `npx petdex install <slug>` puts them) and `pet_read_package` hands the sheet over as a data URL; the sheet is ~2 MB so settings holds only `petdexDir`, never the image. Four things to know: (0) **only the frame size (192×208) and the column count (8) are fixed — the row count is not.** guga is 9 rows (1536×1872), boba is 11 (1536×2288); hardcoding 9 made each cell 254 px and rendered 1.3 characters per frame. `loadPetSprite` therefore derives `frameW = width/8`, `frameH = frameW * 208/192`, `rows = round(height/frameH)`, which also survives sheets drawn at 2× scale. (1) **the row→state table lives in `pet-sprite.ts` and came from petdex's own desktop client, not from their README** — the README's prose lists 8 names for 9 rows in the wrong order, which puts a crying face on `done`; the client's per-row frame counts (6·8·8·4·5·8·6·6·6) match what our alpha scan measures, which is how the table was confirmed. Don't "fix" it back to the README. (2) Rows hold *different numbers* of real frames with the rest left blank, so `loadPetSprite` scans the sheet's alpha on a canvas to count them — animating a fixed 6 or 8 frames makes the pet vanish mid-loop. (3) Sprite frames are 192×208, i.e. taller than wide, so `petdexAspect` is stored in settings and fed to `petWindowSize()`; `PetSpriteFigure` also deliberately skips `.pet-figure`, because the artwork already animates and stacking our CSS bob on top is nauseating.

Body colour is `--ui-chrome`, so the pet recolours with the theme preset. Movement lives in `index.css` under `.pet-mood-*` (plus `.pet-tail` / `.pet-tail-right` / `.pet-antenna` for the moving parts).

**Frequently-used menus are pinned to the rail, not to the sidebar.** The 64 px ActivityBar holds nothing but the menus the user pinned (plus the theme toggle and 설정 at the bottom) — a shortcut that still works with the sidebar collapsed, which is the point (a second list *inside* the sidebar would only duplicate what is already on screen). Pin by right-clicking a sidebar row (왼쪽 레일에 고정) or by **dragging the row onto the rail**; unpin by right-clicking the rail icon or dragging it off the rail (Dock gesture). Pinned menus stay in their group, marked with a small pin, and rail icons carry the menu's own `badge`. Four things this forces:
- **The list lives in a context, not in `useLocalStorage` alone** (`pinned-menus-store.tsx` + `use-pinned-menus.ts`, key `myspace.pinnedMenus`, array order = display order). Two `useLocalStorage` calls on one key in the *same window* never see each other's writes — the `storage` event only fires across windows — so the rail and the sidebar would drift apart. The provider wraps both in `App.tsx`.
- **Drag crosses two components, so the hand-off is DOM-based**: the rail marks itself with `PIN_DROP_ATTR` and the sidebar's existing pointer-drag (WKWebView has no usable HTML5 drag) checks `elementFromPoint(...).closest("[data-pin-drop]")` on pointerup. The only shared state is `dragMenuId`, which tells the rail to show its "여기에 고정" slot; hover feedback is the rail's own `onPointerEnter` (no pointer capture is taken anywhere, so those still fire mid-drag).
- **Rail badges mount a second copy of the badge component.** For the context-reading ones (Slack/Gmail/Claude) that is free. `ServicesMenuBadge` used to own a per-instance poll, which made every extra copy cost one more `*_running` call per 60 s — and there are three copies now (IntelliJ 서비스 = `ide`; Cowork 서비스 and IntelliJ Cowork = `standalone`, the same backend, so always the same number), plus one per rail pin. So `use-running-count.ts` keeps the running set in a **module-level store keyed by backend**: `useSyncExternalStore` subscribes, the first subscriber starts the 60 s safety poll + the `<backend>:status` listener, the last one stops them, and the count is shared no matter how many badges mount. A module store rather than a Provider because badges hang off the sidebar, the rail, and pop-out windows alike — a Provider would have to wrap each of those trees, and forgetting one shows a silent 0. Keep the subscribe callbacks module-level constants (`subscribeIde`/`subscribeStandalone`): a fresh closure per render re-subscribes every render, dropping the subscriber count to 0 in between and cycling the poll off and on.
- 설정 → 메뉴 설정 wins: a hidden menu vanishes from the rail too (`hiddenMenuIds()` in `menus.tsx` is the shared judgement), but it is **not** removed from the stored list, so re-enabling the menu brings the pin back.

**화면 공유 (`src/features/screen-share/` + `src-tauri/src/screenshare.rs`): the app is a *server*, not a capturer.** WKWebView does not support `getDisplayMedia()` — Apple only allows `getUserMedia` in the embeddable webview ([wry#1101](https://github.com/tauri-apps/wry/issues/1101)) — so the two options were (a) capture in Rust with ScreenCaptureKit and hand-roll H.264/VP8 + RTP, or (b) let the system browser capture and have the app only hand out URLs and relay signalling. This is (b): zero video-codec dependencies, and quality/latency are whatever Chrome's hardware encoder gives. `screenshare_start` opens `http://127.0.0.1:P1/s/<sender_token>` in Chrome (`open -a "Google Chrome"`, falling back to the default browser), the page calls `getDisplayMedia`, and the app's `Hub` relays SDP/ICE between that one sender and N viewers. Media never passes through the app. Five things this forces:
- **Two listeners, because of secure context.** `RTCPeerConnection` and `getDisplayMedia` only exist in a secure context. The sender is fine over plain HTTP because `http://127.0.0.1` is the localhost exception — no certificate warning. But a viewer opening `http://<LAN IP>` gets **no WebRTC at all**, so LAN viewers need HTTPS: `build_tls` mints a self-signed cert per session (`rcgen`, SAN = localhost + 127.0.0.1 + the LAN IP) for a second listener on `0.0.0.0:P2`. The viewer clicks through one warning; a tunnel avoids it. Don't "simplify" this to a single HTTP listener — the viewer page would load and then do nothing, which reads as a bug in the video path.
- **The HTTP listener is bound to 127.0.0.1 deliberately.** A warning-free plaintext origin must not be reachable from the network. cloudflared is pointed at *that* origin (`--url http://127.0.0.1:P1`) so there's no `--no-tls-verify` and the public TLS is terminated by Cloudflare.
- **There is no TURN server, so P2P is not enough — hence the relay fallback.** Signalling goes through the app, media is P2P, and on a different network STUN hole-punching often fails behind symmetric NAT or a corporate firewall. Rather than leave the viewer on a black screen, the viewer page falls back: on `connectionState` `failed`/`disconnected`, or after `P2P_TIMEOUT_MS` (8 s) without `connected`, it sends `{type:"relay",on:true}` and the sender tab starts pushing canvas→JPEG frames (5 fps, ≤1600 px, q=0.6) over the same WebSocket, which `Hub::broadcast_frame` fans out. So **anywhere the URL opens, the screen shows** — degraded, not broken. Three details: frames go *only* to the relay set (sending to a P2P viewer doubles upload for nothing); the sender drops frames when `bufferedAmount` exceeds 2 MB or a `toBlob` is still encoding, because a backed-up queue turns into snowballing latency; and `sender_socket` must send `relay-count` on attach as well as on change — a re-opened sender tab that only got `peers` would leave an existing relay viewer frozen. When P2P later reaches `connected`, the viewer sends `on:false` and returns to full quality.
- **Tunnels are cloudflared only. An SSH reverse tunnel (`localhost.run`) was tried and removed — don't bring it back.** It needed no install, and HTTP + WebSocket upgrade both verifiably passed through it, but a real share over it didn't work and it's a free shared service with no bandwidth or availability guarantee. A path that works sometimes is worse than no path: the failure surfaces as "the URL opens but the screen never appears", with nothing to point at. `rejects_the_removed_ssh_tunnel_domain` pins that `*.lhr.life` is no longer accepted. Consequence: without `cloudflared` there is **no** 사외 주소, so `screenshare_tunnel_available` is queried when the 뷰 mounts and the checkbox is disabled with a `brew install cloudflared` hint *before* starting — telling someone it failed after they've already sent an invite is too late. `extract_tunnel_url` still scans *every* `https://` on a line (cloudflared logs its docs URL too) and requires the `TUNNEL_DOMAIN` suffix. A public-IP URL (`https://<WAN IP>:port`) is not an option at all: this PC is behind corporate NAT, so it needs a firewall port-forward, which is IT's call.
- **`rustls` needs its CryptoProvider chosen explicitly.** Both ring and aws-lc-rs are in the dependency graph, so automatic selection panics; `ensure_crypto_provider()` installs ring once. `install_default` returns `Err` on every call after the first — treating that as a failure would make restarting a share impossible, which is why the test asserts `build_tls` twice.
- **A viewer URL must never contain loopback; the sender path must be localhost-only.** These are the same coin. `127.0.0.1` appears in exactly three places — the sender page URL, the tunnel's origin, and the cert SAN — and `viewer_urls_never_point_at_loopback` pins that the URLs handed to other people never do (a recipient opening one would see *their own* machine). Conversely `is_local_host` gates `/s/<token>` and `role=sender` on the `Host` header: the HTTP listener is bound to 127.0.0.1, but the tunnel uses it as its origin, so without that check a leaked `sender_token` lets someone outside attach as sender and replace what's on screen. The sender tab shows and copies those same URLs — it gets them over the socket as a `urls` message pushed from `emit_state`, not once at connect, because the tunnel URL only becomes available seconds later. Also `lan_ips()` returns **every** usable IPv4 (via `getifaddrs`, primary route first, loopback/link-local dropped) and the 뷰 lists them all — this machine is on wired `172.16.100.225` *and* Wi-Fi `192.168.11.94` at once, so publishing only the routed one locks out anyone on the other network. All of them go into the cert SAN too, or the second address adds a name-mismatch warning on top of the self-signed one.
- **Two tokens, not one.** The viewer link and the sender page carry *different* tokens, or anyone holding the viewing URL could attach as sender and replace what's on screen. `Hub` also keys the sender by an id: when a second sender tab attaches, the old one is told `replaced`, and `detach_sender` compares ids so the late-closing old socket doesn't tear down the new sender. Route patterns live in `build_router()` (state applied separately) because a bad axum pattern panics at `route()` — at share-start time, not compile time — so a test calls it.

**Slack 안 읽음 (`src/features/slack/` + `src-tauri/src/slack.rs`): 채널은 고른 것만, DM 은 고르지 않아도 전부 — 대신 봇은 뺀다.** 채널은 수백 개라 사용자가 고른 것만 확인하지만, **DM·그룹 DM 은 선택과 무관하게 항상 대상이다**: 개인에게 직접 온 말은 거의 항상 중요한데, 그걸 사람마다 하나씩 미리 골라 두는 것은 애초에 불가능하다(누가 언제 처음 말을 걸지 알 수 없다). 그 대가로 **자동 포함된 대화에서만 봇·앱 메시지를 세지 않는다** — 앱 DM(Jira·Google Drive·Statuspage …)까지 개인 메시지로 치면 자동 포함이 곧 소음이 되기 때문이고, 반대로 **사용자가 직접 고른 채널에서는 절대 거르지 않는다**(봇 알림 채널은 그걸 보려고 고른 것이다 — `is_system_subtype` 의 경고와 같은 규칙). 여섯 가지가 이 모양을 정한다:
- **봇 판정은 `bot_id` 가 주력이고 `subtype` 은 보조다.** 실측: Jira·Google Drive DM 의 메시지는 `subtype` 이 **없고**(`None`) 평범한 사용자 id 를 달고 오며, 봇임을 알려 주는 것은 `bot_id` 뿐이다. `subtype == "bot_message"` 만 봤다면 여덟 개 중 **하나도** 못 걸렀다. Slackbot 은 또 둘 다 없이 `user: USLACKBOT` 로만 구분되므로 `is_bot_message` 는 세 가지를 모두 본다.
- **전부 매번 확인하는 것은 불가능하다 — 그래서 회전 스캔이다.** 실측 DM 173개(1:1 80 + 그룹 93)에 `conversations.info` 는 Tier 3(분당 50회)이고 선택 채널도 **같은 버킷**을 쓴다. 한 번에 전체 안 읽음을 주는 API 는 없다(`users.counts`·`client.counts` 는 `not_allowed_token_type`, `im.list`·`mpim.list` 는 폐기). 그래서 `pick_dm_targets` 가 `DM_SCAN_PER_POLL`(24)개씩 커서를 돌리며 나눠 확인한다 — 한 바퀴 ≈ 7주기(≈14분).
- **대화 목록의 `updated` 로 선별하려 들지 말 것.** 활동 시각처럼 보이지만 아니다: 실측에서 `updated` 가 최신 메시지보다 **14일 뒤처진** 대화가 있었고(반대로 메시지 없이 두 달 앞선 것도 있었다), 이걸 "최근 활동" 필터로 쓰면 정작 활발한 DM 이 스캔에서 빠진다.
- **`hot` 은 최적화가 아니라 정확성 장치다.** 지난번 안 읽음이 있던 대화는 회전과 무관하게 매번 확인한다. 펫 알림의 `stillUnread`(`pet-notify-publisher.tsx`)가 "응답에 없다 = 읽었다" 로 판정하기 때문인데, 회전만 있으면 아직 안 읽은 DM 의 알림이 자기 차례가 아닐 때마다 조용히 사라진다. **이 규칙을 지우려면 프론트의 판정부터 바꿔야 한다.**
- **`unread_count_display` 를 믿는 곳은 자동 DM 딱 하나다.** 1:1 DM 에는 실려 오는 것이 실측으로 확인돼(안 읽음이 있는 DM 이 `1` 을 돌려줬다) "0이면 히스토리를 건너뛴다" 로 호출을 절반으로 줄인다. 대가는 **그 값이 스레드 답글을 세지 않는다**는 것 — 채널 타임라인은 비었고 스레드 답글만 안 읽은 DM 은 놓친다. 그룹 DM 에는 이 값이 아예 없어 그대로 히스토리를 본다.
- **빈 화면의 기준은 선택 개수가 아니라 결과다.** DM 이 자동 포함되므로 채널을 하나도 고르지 않아도 카드가 뜬다. `slack-view.tsx` 가 `selected.length === 0` 으로 "채널을 고르세요" 화면을 띄우면 안 읽은 DM 이 있는데도 빈 화면이 된다.

**데이터베이스 뷰어 (`src/features/db-viewer/` + `src-tauri/src/db.rs` + `src-tauri/resources/MySpaceJdbcBridge.java`): the app talks JDBC through a Java sidecar, not a Rust driver.** ES needed one HTTP proxy and Kafka had a Rust client, but the five engines asked for here — MySQL/MariaDB, PostgreSQL, Oracle, H2, SQLite — do not share a Rust path: **Oracle has no pure-Rust driver** (the `oracle` crate needs a natively-installed Instant Client) and **H2 has none at all** (Java-only protocol). Splitting the backend per engine would fork query, edit and commit five ways, so everything goes over JDBC. That is cheap here specifically: this is a Java shop with Java 17 on `PATH` and all four driver jars already in `~/.m2`. Also note `sqlx`'s sqlite driver is **not** an option even if you wanted it — it pulls `libsqlite3-sys` 0.30 while `rusqlite` 0.31 (Chrome cookies, `flex.rs`) pins 0.28, and two versions of a `links` crate is a hard cargo error. Nine things this forces:
- **The bridge source is `include_str!`'d and unpacked to `~/.myspace/jdbc-bridge/`, then run as `java <file>`** (JEP 330 single-file source mode). No build step, no `bundle.resources` entry, and dev and release resolve identically — a bundled resource would need two different paths. It is rewritten only when the content hash differs, so `java` keeps its cache.
- **`DriverManager` is deliberately unused.** It refuses drivers loaded from anywhere but the system classloader, and driver jars are read at *runtime* with a `URLClassLoader` (that is what lets one bridge serve Oracle and H2 in the same process). So the bridge instantiates `java.sql.Driver` reflectively and calls `driver.connect(url, props)` itself.
- **`System.out` is swapped to stderr on the first line of `main`.** stdout is the JSON-Lines protocol; a driver printing one warning there desynchronizes every subsequent response. Responses go to a `PrintStream` opened on a dup of the real `FileDescriptor.out`. Symmetrically, Rust **must keep draining the bridge's stderr** or the pipe fills and the JVM blocks.
- **On stdin EOF the pool is `shutdown()`, never `shutdownNow()`.** This was measured: `shutdownNow()` killed in-flight tasks and every response after the first vanished when requests were piped in.
- **Cell values cross the wire as `string | null`, never as JSON numbers.** `BIGINT 9007199254740993` becomes `…992` in a JS double. `null` stays distinct from `""` all the way into the grid, or a NOT NULL column silently receives an empty string.
- **Grid edits accumulate in the frontend and commit as a batch; a JDBC transaction is not held open while the user thinks** (that would hold locks for as long as the window is up). `opApplyChanges` flips autoCommit off for the batch, applies, commits, restores — so the batch is atomic either way. **UPDATE/DELETE that does not affect exactly 1 row rolls the whole batch back**: a stale screen or a non-unique key would otherwise rewrite someone else's row. Editing needs a primary key; without one (or on a view) the pane goes read-only and says why.
- **Paging is dialect-aware with a universal fallback.** Oracle 12c+ gets `OFFSET … FETCH NEXT`, the other four get `LIMIT … OFFSET`; any `SQLException` retries via `setMaxRows` + skipping rows, which is slower but works everywhere (that is also the Oracle 11 path).
- **The qualified name uses schema *or* catalog, never both.** MySQL puts the database in the catalog and PostgreSQL puts it in the catalog *and* has a meaningful schema — emitting `catalog.schema.table` breaks PostgreSQL with "cross-database references are not implemented".
- **The JVM is not kept alive.** `db_bridge_info` only shells `java -version` (it runs on every tab open — spawning a 100 MB JVM for a tab nobody connected from is exactly the memory sin the browser section is about), and `db_disconnect` tears the bridge down when the bridge reports `remaining == 0`. Passwords never touch localStorage: `db_connect` takes the plaintext, and Rust keeps it AES-encrypted under a machine-bound key in `~/.myspace/db-secrets.json` (0600). That encryption is **duplicated from `flex.rs` on purpose** — sharing the key namespace would mean a change on one side invalidating the other's stored secrets.

**IntelliJ HTTP (`src/features/intellij-http/` + `src-tauri/src/http_file.rs`): the `.http` file is the source of truth, and IntelliJ is not involved.** 개발 → IntelliJ HTTP opens the `.http`/`.rest` files of an IntelliJ project, edits them in place, and runs the requests. It deliberately does **not** go through the IDE the way IntelliJ 서비스 does: the MCP tool it would have to use is `execute_run_configuration`, which needs a saved *HTTP Request run configuration* per request — the files here hold 2949 requests across ~400 files, none of them a run configuration. So the client is reimplemented, which also means it works with IntelliJ closed (only the project dropdown borrows `intellij_recent_projects`, and 폴더 직접 선택 covers the rest). Six things this forces:
- **The parser lives in the frontend, the socket in Rust.** `http-parse.ts` must run in the same tick as the keystroke — the gutter ▶ needs "which request is the caret in" and unresolved `{{vars}}` must go red while typing; moving it to Rust would put an IPC round-trip on every character. Rust only does file IO and `http_send`, because the webview can't fetch arbitrary hosts (CORS, same as `es.rs`) and `.http` files routinely set `Host` and `Cookie`, which the browser forbids.
- **The request body is a list of byte chunks, not a string.** A body line can be `< ./profile.jpg`, and multipart requests are written with their boundaries and part headers literally in the file — so the real body is "text · file bytes · text". Text includes are read by the frontend (so `{{var}}` inside them is substituted, as IntelliJ does) and passed as text; only non-UTF-8 files are passed as a path for Rust to read as bytes. Also: when `Content-Type` is `multipart/*` the text chunks and the separators are converted to CRLF — most multipart parsers require it and `.http` files are LF.
- **Response handler scripts are actually executed** (`http-script.ts`, `new Function`). They appear 1980× in this repo and are almost always `client.test`/`client.assert` or `client.global.set("access_token", …)`; skipping them would break the login → token → next request flow, which is half of what the feature is for. The scripts come from the file the user just opened in their own repo, so a real sandbox isn't worth the weight (`tauri.conf.json` has `csp: null`, so `new Function` is allowed).
- **The globals a handler sets are read from a ref, not from state.** 전체 실행 is one async loop, and each `run` closes over the `globals` it was built with — with state alone, request #2 never sees the token request #1 just stored. `globalsRef` is updated synchronously in `applyGlobalUpdates`; the localStorage state (per project) only follows for display.
- **Variable precedence is request → global → in-file `@var` → environment**, and the environment comes from `http-client.env.json` + `http-client.private.env.json` looked up from the file's own folder upwards to the project root, nearest winning, private over public. `{{$env.NAME}}` (OS environment) is **not** supported and shows as unresolved; nothing in this repo uses it and the webview can't read the process environment.
- **`target`/`build`/`.idea` are skipped when walking.** Maven copies `src/test/resources/http` into `target/test-classes/http`, so without that skip every file appears twice and edits land on the copy; `.idea/httpRequests/http-requests-log.http` is IntelliJ's own request log, not a file anyone edits. The editor is a highlighted `<pre>` under a transparent `<textarea>` with soft wrap off (line numbers must line up with logical lines) and the **outer** container scrolling, which is what lets the gutter be `sticky left-0`.
- **Syntax colours come from `--http-*` (index.css), not from the preset tokens.** They are IntelliJ HTTP Client's own palette (구분자 올리브 · 메서드/리터럴 주황 · 헤더 이름·JSON 키 보라 · 문자열 초록 · 숫자 청록, light/dark pair), because inside a code editor the tokens must stay distinguishable from each other no matter which theme preset paints the chrome — wiring them to `ui-info`/`ui-warning` made a keyword and a header name collide on some presets. Only the `{{var}}` resolved/unresolved signal keeps `ui-success`/`ui-error`, since that is a status, not a token type.

**서비스 콘솔의 구문 강조 (`src/features/intellij/console-highlight.ts`): 색은 로그가 직접 정하고, 우리는 옮기기만 한다.** IntelliJ 서비스와 Cowork 서비스는 같은 `ConsolePanel` 을 쓰므로 이 규칙도 하나다. IntelliJ 콘솔이 색을 입히는 방법은 로그 자체의 ANSI 를 해석하는 것뿐이고, 그 ANSI 는 Spring Boot 의 `ColorConverter`(logback 패턴의 `%clr(...)`)가 만든다 — 그러니 **같은 화면을 만드는 방법은 우리가 로그를 해석하는 게 아니라 애플리케이션이 색을 켜게 하는 것**이다. 파이프로 읽으면 Spring Boot 의 `detect` 가 색을 스스로 끄므로 `standalone.rs` 가 `-Dspring.output.ansi.enabled=always` 를 붙인다(IDE 가 Spring Boot 실행 설정에 붙이는 것과 같은 값). 이렇게 하면 커스텀 패턴이 바뀌어도, 서드파티 라이브러리가 자기 색을 써도 그대로 따라간다. 네 가지가 따라온다:
- **패턴 파서는 보조지, 주 경로가 아니다.** ANSI 가 한 글자도 없는 줄에만 도는데, 그런 줄은 두 군데서 온다 — IDE 로그 동기화(IntelliJ 가 파일로 남긴 콘솔)와 이미 떠 있던 프로세스를 흡수한 경우. 둘 다 우리가 색을 켤 기회가 없었던 로그다. 아는 모양은 cowork 공용 logback 설정(`share-logging/.../logback-spring.xml` 의 `%d %5p [traceId,spanId] [%10.10t] %-40.40logger{39}:%3L %-15.15M %m`)과 Spring Boot 기본 패턴 둘뿐이고, **어느 쪽도 아니면 색을 입히지 않는다** — 잘못 칠하는 것이 안 칠하는 것보다 나쁘다.
- **라인번호는 메서드 필드의 폭까지 맞아야 인정한다.** `%3L %-15.15M` 을 그냥 "숫자 다음 낱말" 로 읽으면 `: 42 rows updated` 같은 평범한 메시지가 라인번호 + 메서드로 칠해진다. `%-15.15M` 은 15자로 패딩되고 뒤에 구분 공백이 하나 더 붙으므로 "메서드 + 뒤 공백 ≥ 16" 을 조건으로 걸어 걸러낸다.
- **색은 `--console-*` 16색(index.css), 프리셋 토큰이 아니다.** `--http-*` 와 같은 이유다 — 이 값들은 로그가 찍은 ANSI 번호를 옮긴 것이라 프리셋이 바뀌어도 같은 뜻이어야 한다. 다크는 Darcula 값 그대로지만 **라이트는 초록·노랑·청록·흰색만 한 단계 어둡게** 잡았다: IntelliJ 원값(`#00CD00` 등)은 흰 배경 대비가 2:1 언저리인데 INFO 가 초록이라 거의 모든 줄이 그 색이 된다.
- **클래스 이름은 조립하지 말고 통째로 적는다.** Tailwind v4 는 소스를 글자로 훑으므로 `text-${color}` 로 만들면 `text-console-red` 라는 글자가 어디에도 없어 규칙이 생성되지 않는다 — 에러 없이 색만 사라진다. `LogLine` 이 `memo` 인 것도 규칙이다: 줄이 하나 붙을 때마다 배열이 새로 만들어지는데, 줄 문자열은 그대로라 memo 가 나머지 수천 줄의 재파싱을 전부 막는다.

**Git (`src/features/git/` + `src-tauri/src/git.rs`): the `git` CLI is the backend, not libgit2.** 개발 → Git is the IntelliJ Git tool window for the one repo 설정 → Cowork points at (`settings.cowork.home`, the same value the spec docs and the service launcher use — `repo_root()` runs `rev-parse --show-toplevel`, so a subfolder resolves to the root and every path in the API is root-relative). Shelling out to `git` rather than linking `git2` buys three things: **credentials** (push goes to the corporate remote, so `osxkeychain` and `~/.ssh/config` must work — libgit2 reimplements both and needs libssh2 linked), **the user's `.gitconfig`** (hooks, gpg signing, `core.autocrlf`, `include`; without it a commit made here differs from one made in the terminal), and no extra build weight. Eight things that choice forces:
- **Only machine-readable output is parsed.** Status is `--porcelain=v1 -z --untracked-files=all --branch` — NUL-separated so paths are never quoted or escaped (Korean and spaces come through as-is) — and stash is `--format=%gd%x00%gs%x00%cr`. **A rename entry occupies two slots** (`R  new\0old\0`), so the parser walks the iterator by hand and pulls the extra one; miss it and every file after the rename shifts by one, which fills the list plausibly and silently. `collects_status_from_a_real_repo` builds an actual repo and pins that.
- **`GIT_TERMINAL_PROMPT=0` and `GIT_OPTIONAL_LOCKS=0` on every call.** Nobody can answer a tty prompt from inside the app, so a credential-less push would hang forever instead of failing; and status is *polled*, so it must not rewrite the index and fight `index.lock` with the terminal or IDE running beside it.
- **Every command is `async` + `spawn_blocking`.** Sync Tauri commands run on the main thread, and push/pull are network calls — the whole window would freeze for their duration.
- **Checkboxes are the commit set, nothing else.** Stage / unstage / rollback / stash are per-file actions on the **right-clicked row only**. Hanging destructive actions off the checkboxes makes it impossible to predict what a click deletes.
- **Commit reconciles the index with the screen before committing**, IntelliJ-style: staged-but-unchecked paths are reset, checked paths are added, then `commit -m`. Without the reset step, anything another tool left staged rides along invisibly.
- **Rollback re-reads status in Rust instead of trusting the list the frontend is holding** (it may be seconds stale, and guessing wrong here deletes a file), then branches three ways: untracked → delete the file; staged-add (`A`) → `rm --cached` only, leaving the file as unversioned, which is what IntelliJ does; everything else → `checkout HEAD --` over index *and* worktree, plus the rename's original path or the old name stays gone.
- **Untracked "diffs" are synthesized by reading the file**, not `diff --no-index /dev/null <f>` — that path needs exit code 1 treated as success and `/dev/null` is Unix-only. Binary (a NUL byte) and >1 MB files get a one-line note instead of a body.
- **Polling is gated on `useTabActive()` *and* paused while an action runs** (`busy`). The first is the standard keep-alive rule; the second is because commit and rollback change the index in several steps, and a snapshot read mid-sequence makes files blink out of the list and back.
- **IntelliJ Cowork 의 트리 우클릭에도 Git 이 둘 있다(`Git ▸ Add` / `Show History`), 그리고 그 경로는 저장소 루트 상대가 아니라 *절대 경로*다.** `git` 은 저장소 안의 절대 경로를 pathspec 으로 그대로 받으므로(파일·디렉터리 모두 — 테스트로 확인), 추가는 기존 `git_stage` 를 그대로 쓰고 이력은 `git_file_history` / `git_commit_file_diff` 가 받는다. 프론트에서 루트 상대로 바꾸지 **않는** 이유는 `settings.cowork.home` 이 저장소의 하위 폴더일 수 있어 그 변환이 틀리기 쉽다는 것이다(`git-marks.ts` 가 색 표의 키를 절대 경로로 두는 것과 같은 판단). 이력은 파일일 때만 `--follow` 를 붙이고(디렉터리에 주면 git 이 거부한다), 오른쪽 diff 는 `show <hash> -- <path>` 라 **이름이 바뀐 파일의 옛 커밋은 빈 diff** 가 된다 — 그 시점의 경로가 지금 이름이 아니기 때문이고, 커밋마다 옛 경로를 되짚는 비용은 이 화면이 낼 것이 아니다. 트리의 Git 묶음은 `gitHome`(= `git_status` 가 성공한 홈)이 있을 때만 달리고 **빈 자리 우클릭(=루트)에는 달지 않는다**: 루트에 `git add` 를 걸면 한 번의 클릭이 프로젝트 전체를 스테이지에 올린다.

**할 일의 마크다운 폴더 저장 (`src/features/todo/use-todo-folder-sync.ts` + `src-tauri/src/todo_store.rs`): Obsidian·Dropbox·iCloud·git 을 위한 코드는 없다 — 전부 "폴더 하나"다.** 요구는 "할 일을 Notion·Dropbox·Obsidian 에 저장"이었지만, **Obsidian 볼트는 그냥 마크다운 폴더**이고 Dropbox·iCloud·Google Drive 도 로컬에서는 폴더이며 git 저장소도 폴더다. 그래서 `settings.todo.folder` 하나가 Obsidian 편집·기기 간 동기화·변경 이력을 동시에 해결한다. **Dropbox API 를 붙이지 않는 것은 의도다** — 폴더에 쓰면 Dropbox 앱이 훨씬 안정적으로 올려 주고, 우리는 OAuth·토큰 갱신·rate limit 을 하나도 갖지 않는다. Notion 만 진짜 API 작업으로 남아 있고 아직 없다. **카테고리가 폴더 하나, 포스트잇이 그 안의 파일 하나**(`<루트>/릴리스/릴리스 준비.md`)이고, 할 일이 `- [ ]` 다. 포스트잇을 헤딩이 아니라 파일로 두는 것이 핵심이다 — Obsidian 에서 포스트잇 하나가 노트 하나가 되므로 링크·백링크·검색·그래프가 동작하고, **노트를 다른 폴더로 끌면 카테고리가 바뀐다**. 카테고리 자신은 폴더 안의 숨은 `.myspace-category.md`(id·이름·순서)이고 휴지통은 숨은 `.myspace-trash/` 폴더다. 감시는 **mtime 폴링**이지 `notify` 크레이트가 아니다(훑는 범위가 루트와 폴더 한 겹뿐이라 `read_dir` 이 싸고, 이 저장소의 다른 감시도 전부 폴링이다). 열두 가지가 이 모양을 정한다:
- **localStorage 를 대체하지 않고 캐시로 남긴다.** 파일을 직접 상태로 쓰면 폴더가 없는 기본 사용자를 위해 두 갈래 코드를 유지해야 하고, 타이핑마다 파일 왕복을 기다리게 되고, 팝아웃 창과 메인 창이 `storage` 이벤트로 공유하던 상태가 갈린다. 폴더가 비어 있으면 `useStickies` 는 예전과 **한 줄도 다르지 않게** 동작한다.
- **파일이 하나도 없으면 상태를 건드리지 않는다.** `pull` 이 무조건 적용하면 데이터가 쌓인 보드에 빈 폴더를 지정하는 순간 보드가 비워지고, 폴더가 잠깐 사라지는 상황(외장 디스크 분리, Dropbox 재동기화, 볼트 이동)마다 같은 일이 벌어진다. **지우는 방향으로는 자동 반영하지 않는다** — 진짜 비우고 싶으면 앱에서 지우면 그게 파일로 나간다. 처음 폴더를 지정할 때의 방향도 이 규칙이 정한다: 파일이 있으면 파일이 이기고(다른 기기에서 쌓아 둔 것을 방금 켠 빈 보드로 덮으면 안 된다), 없으면 지금 보드를 내보낸다.
- **`myspace-todo` 표식이 있는 파일만 읽고 쓰고 지운다.** 지정한 루트가 볼트일 수 있는데 파일명만 보고 관리하면 남의 노트를 지운다. 카테고리 폴더 안에 사람이 넣어 둔 노트도 읽지 않고 지우지 않으며, 그런 파일이 남아 있으면 카테고리를 지워도 폴더는 남는다(`remove_dir` 는 빈 폴더만 지우므로 그 판단이 공짜로 따라온다). 깊이는 **딱 한 단계**다. `never_touches_files_without_our_marker` 가 이 계약을 붙든다.
- **포스트잇의 카테고리 소속은 파일에 적지 않는다 — 위치가 정한다.** 적으면 Obsidian 에서 노트를 옮겼을 때 위치와 내용이 서로 다른 말을 하고, 어느 쪽을 믿을지 정하는 규칙이 하나 더 생긴다. 휴지통 항목만 예외로 `category:` 를 들고 있다(숨은 폴더 하나에 모여 있어 위치가 알려 줄 수 없고, 복원할 곳을 알아야 한다).
- **파일명이 곧 제목이고 정체성은 `id:` 다.** 앱에서 제목을 바꾸면 파일이 옮겨 가지만 같은 포스트잇이고, 사람이 파일명을 바꾸면 그것이 새 제목이 된다 — `matches_stem` 이 "파일명이 여전히 이 제목에서 나온 것인지"로 가른다. 파일명을 무조건 믿으면 `a/b` 처럼 파일명에 못 쓰는 글자가 든 제목이 조용히 `a_b` 로 바뀌고, frontmatter 를 무조건 믿으면 Obsidian 에서 한 이름 바꾸기가 매번 되돌려진다.
- **제목이 비거나 겹칠 때의 파일명 접미사는 순번이 아니라 id 다.** 새로 만든 포스트잇은 제목이 비어 있는 게 정상인데, 그것들을 `무제`·`무제-2` 로 번호 매기면 포스트잇 **순서를 바꿀 때마다** 번호가 밀려 파일이 통째로 지워지고 다시 만들어진다(`empty_titles_survive_reordering` 이 이걸 붙든다). 그래서 `무제-a1b2c3d4.md` 다.
- **순서는 `order:` 가 담는다.** 파일 시스템에는 순서가 없으므로 카테고리 순서 변경과 포스트잇 순서 변경이 모두 이 값으로 나간다. 지문(signature)에 **폴더 이름도 넣는** 이유가 여기 있다 — 카테고리 이름 변경은 폴더 이름만 바뀌는 일이라 파일 mtime 만 보면 놓친다.
- **예전 배치(카테고리 하나 = 루트의 파일 하나, 포스트잇이 `##` 헤딩)도 읽는다.** 첫 구현의 파일이 남아 있으면 그대로 읽어 들이고 다음 저장에서 새 배치로 옮겨진 뒤 옛 파일은 정리된다(우리 표식이 있으니 지워도 안전하다). `migrates_the_first_layout_where_a_category_was_one_file` 이 그 이관을 검증한다.
- **되읽기 왕복을 막는 장치가 두 개다.** 쓰기가 끝나면 Rust 가 그 직후의 mtime 지문을 돌려주고 폴링은 지문이 같으면 아무 일도 하지 않는다(없으면 우리가 쓴 파일을 우리가 다시 읽고, 그 갱신이 다시 쓰기를 불러 무한 왕복이 된다). 그리고 내용 지문(`fingerprint`)은 **파일에 실제로 적히는 필드만** 이어 붙인다 — `createdAt` 처럼 파일에 없는 값이 바뀌었을 때 파일을 건드리지 않고, 무엇보다 파일에서 읽은 직후에 곧바로 되쓰지 않는다.
- **포스트잇 메타는 frontmatter 에 두지만 할 일 id 는 아예 저장하지 않는다.** 포스트잇에는 `color`(마크다운으로 표현할 수 없는, 앱에서만 고르는 값)와 라운드트립 매칭용 id 가 필요하다. 할 일 항목은 텍스트와 체크 상태가 전부이고 그 id 를 참조하는 곳이 없어 읽을 때마다 새로 만든다 — 덕분에 사람이 실제로 편집하는 본문이 체크박스 목록뿐이다.
- **카테고리 id 는 비워서 넘기지 않고 Rust 가 폴더명으로 채운다.** 포스트잇 id 와 달리 카테고리 id 는 포스트잇의 소속이 참조하는 값이라, 사람이 만든 폴더 두 개가 나란히 빈 id 로 오면 어느 폴더의 포스트잇인지 구분할 수 없다. 폴더명은 그 자리에서 고유하고 안정적이라 임시 id 로 알맞고, 다음 저장에서 `id:` 로 정착한다. **이걸 프론트에서 `randomUUID` 로 채우게 되돌리지 말 것** — 참조가 어긋난다. 같은 이유로 `.myspace-category.md` 가 없는 폴더도 우리 표식이 붙은 노트가 하나라도 있으면 카테고리로 인정한다(사람이 Obsidian 에서 폴더를 만들어 노트를 넣는 것이 자연스러운 조작이다).
- **체크박스가 아닌 줄은 버려진다.** 포스트잇 모델에 자유 본문이 없어 다음 저장 때 사라지고, 설정 화면이 그 사실을 알린다. 보존하려면 모델에 필드를 더해야 한다.
- **카테고리 순서 변경과 포스트잇 카테고리 이동은 각각 두 가지 방법을 준다.** 순서는 레일 행을 끌어서 바꾸고(별도 그립 핸들 없이 4px 이동 임계값으로 클릭과 가른다 — 행이 32px 로 좁고 사이드바도 같은 방식이다. 드래그였는지는 ref 에 남겨 `onClick` 에서 걸러 내는데, 클릭이 `pointerup` 뒤에 오기 때문이다), 이동은 **포스트잇을 카테고리 레일로 끌어다 놓거나** 카드 헤더를 **우클릭**해 칩 목록을 펼쳐서 한다(사이드바 고정과 같은 우클릭 + 드래그 조합이다). 드래그만 두지 않는 이유는 그쪽에 눈에 보이는 단서가 없다는 것이고, 그렇다고 헤더에 아이콘을 하나 더 두지도 않는다 — 카드가 좁으면 제목이 밀린다. 여는 버튼이 없으므로 칩 행에 **닫는 X 가 있어야 한다**(없으면 우클릭으로 연 목록을 되돌릴 수 없다). 같은 이유로 할 일 행의 연필 아이콘도 지웠다: 행마다 아이콘이 둘씩 붙어 글자가 접혔고, 항목을 눌러 편집하는 동작은 그대로 남아 있다. 카드 폭도 브레이크포인트(`lg:grid-cols-3`)가 아니라 `repeat(auto-fill,minmax(min(360px,100%),1fr))` 로 정한다 — 브레이크포인트는 화면 폭만 보므로 사이드바와 레일이 먹는 폭이 빠지면서 카드가 좁아졌다(`auto-fit` 은 포스트잇이 하나일 때 카드를 창 전체로 늘려서 쓰지 않는다). 카드 드래그의 `pointerup` 은 **레일을 먼저 확인**하고(레일 행에는 카드가 없어 겹치지 않는다) 없을 때만 순서 변경으로 처리하며, 옮긴 포스트잇은 대상 카테고리의 **맨 앞**으로 간다(`categoryId` 만 바꾸면 배열 위치가 그대로라 중간에 끼어들어 어디로 갔는지 알 수 없다).
- **`isMainWindow` 로 막지 않는다** — 전역 스케줄러가 아니라 할 일 뷰에 딸린 훅이라, 그렇게 막으면 메인 창에 할 일 탭이 없고 팝아웃만 열려 있을 때 아무도 동기화하지 않는다. 두 창이 같은 내용을 두 번 쓰는 건 멱등이라 무해하다. 폴링 자체는 keep-alive 규칙대로 `useTabActive()` 로 게이트하고, 읽기·쓰기가 도는 동안에는 `busyRef` 로 쉰다(중간 상태를 읽지 않도록). 저장 실패는 뷰 툴바에 반드시 드러낸다 — 조용히 실패하면 사용자가 파일이 최신인 줄 알고 그쪽을 신뢰한다(앱 안의 데이터는 localStorage 에 그대로 있어 잃지는 않는다).

**할 일 → Claude Code 실행 (`src/features/todo/run-panel.tsx` + `run-session.ts`): 세션은 포스트잇에 붙이고, 프롬프트는 할 일마다 갈아 낀다.** 카드 헤더의 🤖 를 누르면 카드 아래에 실행 패널이 펼쳐지고, 거기서 고른 세션이 **그 포스트잇에 남는다**. 할 일 행의 ▶ 를 누르면 그 문구가 패널의 편집칸으로 **복사**되고(전송이 아니다), 다듬은 뒤 실행을 누르면 나간다. **새 세션을 띄우지 않고 이미 열려 있는 세션에 보낸다** — 새 워크스페이스를 만드는 길도 있지만(`herdr workspace create --cwd` + `herdr agent start claude -- claude …`) 그 CLI 는 herdr 에만 있어 cmux·Orca 가 빠지는 반면, 열린 세션에 보내는 쪽은 세션 목록 화면이 쓰는 `herdr_send_prompt` 를 그대로 타므로 `route_of` 덕분에 **세 백엔드가 한 번에** 지원된다. 무엇보다 **"어느 리포에서 돌릴지" 라는 질문이 사라진다** — 고른 세션의 pane cwd 가 곧 작업 폴더라, 카테고리나 포스트잇에 폴더를 저장할 필요도 없고 그 값이 낡을 일도 없다(그 대신 세션을 먼저 띄워 둬야 하는 제약이 남는다). 여덟 가지가 이 모양을 정한다:
- **세션 지정은 마크다운이 아니라 localStorage(`myspace.todoRunSessions`)에 따로 둔다.** 워크스페이스 id 는 터미널이 살아 있는 동안만 유효한 런타임 값이라(herdr 를 다시 띄우면 `w1` 이 다른 작업을 가리킨다) 기기 사이에서 공유되는 볼트 파일에 넣으면 다른 기기에서 무의미하고, 최악의 경우 **엉뚱한 세션을 가리킨다**. `hideDone` 과 같은 "이 기기에서의 보기 설정" 계열이고, 덕분에 `use-todo-folder-sync` 의 지문·필드 규칙을 하나도 건드리지 않는다.
- **그 훅은 `TodoView` 에서 한 번만 부르고 카드에 내려 준다.** 같은 창에서 같은 키로 `useLocalStorage` 를 두 번 부르면 서로의 쓰기를 보지 못하므로(`storage` 이벤트는 다른 창에만 간다) 카드 A 의 지정이 카드 B 의 낡은 스냅샷에 덮여 사라진다 — 사이드바와 레일이 핀 목록을 컨텍스트로 공유하는 것과 같은 함정이다.
- **▶ 는 복사지 전송이 아니다.** 할 일 문구("배포 스크립트 정리")는 사람이 기억하려고 쓴 메모라 지시로는 대개 손을 봐야 한다. 초안은 `포스트잇 제목: 할 일` 인데(할 일만으로는 "버전 올리기" 가 무엇의 버전인지 알 수 없다) 제목이 비면 붙일 맥락이 없으니 그대로 둔다. 실행은 **⌘/Ctrl+Enter 이고 맨 Enter 는 줄바꿈**이다 — 여러 줄로 다듬는 것이 정상인 입력칸에서 Enter 전송은 반쯤 쓴 지시를 보낸다.
- **지정된 세션이 목록에 없으면 조용히 갈아 끼우지 않는다.** 터미널을 닫았거나 herdr 를 다시 띄운 경우인데, 다른 세션으로 슬쩍 옮기면 **엉뚱한 곳에 프롬프트가 들어간다**. `missing` 이면 경고를 띄우고 `<select>` 에 "(이름) — 실행 중 아님" 줄을 남긴다: 선택이 조용히 비어 버리면 무엇을 골랐었는지 알 수 없어 사용자는 지정한 적이 없다고 생각한다(그래서 `RunTarget` 이 `label` 을 함께 들고 있다).
- **세션 이름만으로는 세션이 구분되지 않는다.** 한 리포에서 둘을 띄우면 이름도 폴더도 똑같아진다(실측 — `my-space` 워크스페이스 둘이 같은 `…/my-space/bin`). 그때 유일하게 다른 것이 마지막 프롬프트라, `<select>` 의 각 줄과 고른 세션의 요약줄 모두 `이름 — 폴더 — 마지막 프롬프트` 를 함께 싣는다.
- **pane 은 목록을 만들 때 한 번 찾아 들고 다닌다.** 감시가 켜져 있으면 목록이 800ms 마다 갱신되므로, 전송 시점에 `agentOf` 를 다시 부르면 사용자가 고른 것과 **다른 pane** 으로 갈 수 있다. `agentOf`/`paneOf`/`wsKey`/`byRecent` 는 세션 목록 화면과 공유하려고 `use-herdr.ts` 로 옮겨 두었다(같은 규칙이 두 벌이 되면 한쪽만 고쳐진다).
- **패널은 펼쳤을 때만 렌더한다.** 그 안의 `useHerdr()` 가 `herdr:*` 두 개를 구독하므로, 항상 마운트해 두면 할 일 탭이 열려 있는 것만으로 카드 수만큼 값을 치른다. 반대로 **펼칠 때는 `refresh()` 를 한 번 부른다** — 작업 감시가 꺼져 있으면 이벤트가 아예 오지 않아 목록이 빈 채로 남는다(감시 없이도 지금 떠 있는 세션에는 보낼 수 있다). 접어도 지정은 남으므로 헤더의 🤖 는 **지정돼 있으면 강조**한다: 지정 여부가 펼쳐야만 보이면 이 포스트잇이 어디에 연결됐는지 카드를 봐도 알 수 없다.
- **보낸 뒤 프롬프트만 비우고 패널은 열어 둔다**(할 일 여러 개를 이어서 보내는 흐름이다). **터미널로 이동은 자동으로 하지 않고 토스트의 "이동" 액션에 건다** — 트레이 앱이라 창을 앞으로 끌어오는 것이 방해가 되는데, 필요할 때는 한 번의 클릭이면 된다. 작업 중인 세션에도 보낼 수 있고(`herdr pane run` 이 큐잉한다) 그렇다고 알린다 — 즉시 처리되는 줄 알면 결과를 한참 기다리게 된다.

**사내 계정 (`src-tauri/src/auth.rs` + `src/features/auth/`): 로그인은 평문 389, 비밀번호 변경은 LDAPS 636 — 경로가 갈리는 것은 의도다.** 로그인은 "서비스 계정 바인드 → 사용자 검색 → 사용자 DN 재바인드" 세 단계이고, 설정 → 계정의 **비밀번호 변경**(`ChangePasswordPanel`)은 그 뒤에 한 단계를 더 붙인 것이다 — 사용자 DN 으로 바인드한 세션에서 자기 `unicodePwd` 를 `Delete(옛)` + `Add(새)` **한 번의 modify** 로 바꾼다. 이게 AD 의 "본인 변경"이라 관리자 권한이 필요 없고 도메인 정책(길이·복잡도·히스토리·최소 사용 기간)이 그대로 걸린다 — 관리자 리셋인 `Replace` 와 헷갈리지 말 것. 사내 정책은 31일 만료 + 1일 최소 사용 기간이라 한 달에 한 번 바꿔야 하는데 맥에는 Windows 의 Ctrl+Alt+Del 변경 창이 없다는 것이 이 기능이 있는 이유다. 여섯 가지가 이 모양을 정한다:
- **평문으로는 아예 불가능하다.** AD 는 암호화되지 않은 연결에서 `unicodePwd` 수정을 거부하므로 이 경로만 `ldaps://…:636` 을 쓴다. **로그인까지 LDAPS 로 올리지 않은 것도 의도다** — 지금 잘 도는 로그인을 아래의 인증서 사정에 묶지 않기 위해서다.
- **인증서 검증을 끈다(`NO_TLS_VERIFY`).** 사내 DC 의 인증서(Sectigo 와일드카드)가 **만료** 상태라 검증을 켜면 연결 자체가 실패한다. 사내망이고 서비스 계정 자격증명이 이미 이 파일에 박혀 있어 실익보다 "기능이 아예 안 되는" 쪽이 크다는 판단이다. 인증서가 갱신되면 되돌릴 것.
- **TLS 백엔드는 native-tls 다.** ldap3 의 `tls-rustls` 는 rustls 0.21 을 끌어와 screenshare 가 쓰는 0.23 과 두 벌이 되는 반면, native-tls 는 이미 의존성 트리에 있어 추가 빌드 부담이 없다.
- **`unicodePwd` 값은 따옴표로 감싼 UTF-16LE 다.** `"newpass"` 를 그대로 UTF-16LE 로 인코딩한 바이트. 따옴표를 빼면 AD 가 이유를 알려 주지 않고 거부만 하므로 `encodes_unicode_pwd_as_quoted_utf16le` 가 그 형식을 붙든다.
- **정책과 만료일은 하드코딩하지 않고 매번 AD 에서 읽는다**(`ldap_password_policy` — 도메인 루트의 `minPwdLength`/`pwdProperties`/`pwdHistoryLength`/`maxPwdAge`/`minPwdAge` + 사용자의 `pwdLastSet`). 관리자가 정책을 바꾸면 화면이 조용히 거짓말을 하기 때문이다. 그 노드는 `BASE_DN`(조직 OU)이 아니라 **도메인 루트**(`DOMAIN_DN`)에 있다.
- **폼은 기본으로 접혀 있고, 상시로 보이는 것은 만료 예정일뿐이다.** 이 화면을 여는 이유는 "언제 만료되지?"가 "지금 바꾸자"보다 훨씬 잦은데, 비밀번호 입력칸이 늘 떠 있으면 계정 화면을 열 때마다 입력을 요구받는 것처럼 보인다. 그래서 만료 안내는 항상, 입력칸은 **비밀번호 변경** 버튼을 눌렀을 때만 나오고, 성공하면 다시 접히면서 결과 메시지만 남는다(방금 채운 칸이 그대로 떠 있으면 변경이 됐는지 안 됐는지 읽히지 않는다).
- **클라이언트 검사는 경고까지만이고 차단은 최소한이다.** 길이·재입력 일치처럼 확실한 것만 버튼을 막고, 복잡도·이름 포함 같은 판정은 노란 경고로만 알린 뒤 전송을 허용한다 — 최종 판정자는 AD 이고, 여기서 오탐이 나면 바꿀 수 있는 비밀번호를 바꾸지 못하게 된다. 실패 사유는 rc 가 아니라 **메시지 앞머리의 16진 코드**로 갈린다(`0000052D` = 정책 위반, `00000056` = 옛 비밀번호 불일치). 현재 비밀번호를 틀리면 잠금 카운터(5회)가 올라가므로 그 사실을 메시지에 함께 알린다. ⚠️ 맥북은 AD 에 바인드돼 있지 않으므로(로컬 계정) 여기서 바꿔도 맥 로그인·FileVault 와는 무관하다 — 바인드된 기기가 생기면 이 전제부터 다시 볼 것.

**실행 기록 (`src-tauri/src/firebase.rs`): 누가 앱을 켜 놓았는지를 Firebase RTDB 에 남긴다.** 두 노드뿐이다: `access-log/<YYYY-MM-DD>/<auto id>` 에 `login`/`logout` 한 줄(POST 로 서버가 auto id 를 만들게 두면 같은 밀리초에 두 번 써도 덮이지 않고, 날짜 노드 안에서는 키 순서가 곧 시간순이다), 그리고 **`status/<LDAP 아이디>`** — 사람마다 노드 하나를 PUT 으로 통째 교체한다. 사람별로 나뉘어 있으므로 여러 명이 동시에 켜 놔도 서로 덮어쓰지 않는다.

**기록은 앱 시작이 아니라 로그인이 확정된 시점에 시작된다.** `status` 를 사람별로 가르려면 LDAP 아이디가 필요한데 Rust 는 그 값을 스스로 알 수 없다 — 로그인 정보는 프론트의 localStorage 에만 있다. 그래서 `app_started()` 는 시작 시각 고정과 하트비트 스레드만 띄우고, 실제 기록은 `FirebasePresence`(`src/features/firebase/`)가 `firebase_set_user` 로 사용자를 알려줄 때 열린다(자동 로그인이면 1~2초). 그 컴포넌트에 걸린 두 제약은 지킬 것: **`LoginGate` 바깥에 마운트**해야 하고(안에 두면 로그아웃하는 순간 언마운트돼 로그아웃을 알릴 기회가 사라지고 노드가 `online: true` 로 굳는다), **`isMainWindow` 로 막아야** 한다(팝아웃 창도 같은 `AuthProvider` 를 쓰므로 창을 열 때마다 로그인/로그아웃이 중복으로 오간다). 앱만 켜고 로그인하지 않은 구간은 `status` 에 안 남는데, `LoginGate` 가 막아 어차피 앱을 못 쓰는 구간이라 "아무도 켜 놓지 않았다"가 맞다. 다섯 가지가 이 구현의 모양을 정한다:
- **리전이 URL 에 들어간다.** 이 DB 는 `asia-southeast1` 이라 리전 없는 `*.firebaseio.com` 은 404 + "Database lives in a different region" 을 돌려준다. 콘솔 URL 만 보고는 알 수 없다.
- **종료 기록은 동기여야 한다.** `RunEvent::Exit` 뒤 프로세스는 바로 사라지므로 fire-and-forget 요청은 전송 전에 죽는다. 그래서 `reqwest::blocking`(이 feature 가 붙은 유일한 이유)을 **별도 std 스레드**에서 돌리고 채널로 기다린다 — blocking 클라이언트는 자체 tokio 런타임을 만들어서 Tauri 런타임 스레드에서 직접 부르면 패닉하고, 스레드 분리는 그 패닉 회피이자 `EXIT_WAIT` 타임아웃을 걸기 위한 장치다. 오프라인에서 종료가 몇 초씩 늦어지면 그게 더 큰 버그다. 이걸 잡으려고 `run(context)` 를 `build(context).run(|_, event|)` 로 바꿨다(메인 창의 X 는 트레이로 숨기기만 하므로 실제 종료는 ⌘Q 와 트레이 종료뿐이고, 둘 다 `Exit` 로 들어온다).
- **로그아웃도 종료로 친다.** 앱이 켜져 있어도 LDAP 로그아웃을 하면 그 사람은 더 이상 쓰고 있지 않고, 그 자리에서 다른 사람이 로그인할 수도 있다. 그대로 두면 앞사람 노드가 `online: true` 로 남아 거짓말을 하므로, `firebase_set_user` 는 사용자가 바뀌면 앞사람을 먼저 닫고(`reason: "switch-user"`) 새 사람을 연다. 같은 사용자로 다시 불리면 무시한다 — 창을 여닫을 때마다 `access-log` 에 같은 로그인이 쌓이면 안 된다.
- **`status` 키는 다듬어서 쓴다.** RTDB 키에는 `.` `$` `#` `[` `]` `/` 를 넣을 수 없는데 `auth.rs` 는 사용자가 입력한 UPN(`kmhan@spectra.co.kr`)을 그대로 돌려줄 수 있어서, 그대로 PUT 하면 400 이 떨어진다. `status_key()` 가 금지 문자를 `_` 로 바꾸고, 원본은 노드 안 `user` 필드에 남는다.
- **`kill -9` 와 `tauri dev` 의 재시작에는 `logout` 이 남지 않는다.** 그때 `online` 이 `true` 로 굳는 걸 막으려고 `lastSeen` 을 60 초마다 PATCH 한다 — `online: true` 인데 `lastSeen` 이 한참 전이면 비정상 종료로 읽으면 된다. 하트비트를 지우려거든 이 판정을 대체할 것부터 정할 것.
- **어떤 실패도 앱에 영향을 주지 않는다.** 시작 기록은 스레드로 빠져 창 뜨는 걸 붙잡지 않고, 실패는 `log::warn!` 한 줄로 끝난다. 실행 기록 때문에 앱이 안 켜지면 안 된다. 통합 테스트(`#[ignore]`)는 `_test` 노드에만 쓰고 지우며, `two_users_get_independent_status_nodes` 가 "한 사람이 나가도 다른 사람 노드는 그대로"를 실제 DB 에 대고 확인한다(사람별로 가른 이유가 바로 그것이라 이 테스트가 그 계약을 붙든다). 그쪽은 `access-log` 에 `_test-` 사용자 흔적이 남으니 돌린 뒤 날짜 노드를 확인할 것. ⚠️ 현재 RTDB 규칙은 **완전 공개**(테스트 모드)라 URL 만 알면 누구나 읽고 쓴다 — 규칙을 잠그면 REST 호출에 인증 토큰이 필요해지므로 여기부터 고쳐야 한다.

**Claude Code watching has three backends — herdr, cmux and Orca, and only those three.** 세션 목록 (`src/features/claude-bridge/`) needs two things from the terminal side: (a) which pane is which **Claude `session_id`**, and (b) whether that session is working / blocked / done. herdr answers both over its socket CLI; cmux answers both through its event log; Orca answers both through its hook status file. A plain terminal emulator (Ghostty, iTerm2, Terminal) answers *neither* — Ghostty's AppleScript (1.3.0+) exposes `working directory` and can send input, but cannot read the screen and has no session mapping, so the list can't be filled. That's why `settings.claudeCode.backend` is a **list** (`ClaudeWatchTerminal[]`, persisted comma-joined) and the settings panel says only those three terminals are supported. **All three on is the default**, because any one alone shows part of the picture: herdr alone misses sessions started straight from the other two, and cmux alone **collapses herdr's workspaces into one tab** (they inherit the same `CMUX_WORKSPACE_ID`, so several tasks land in one card and 이동 only reaches the tab). Merging is safe because every backend carries the same Claude `session_id` — that's the dedup key. `dup_workspaces()` drops a *workspace* (not just the session) whenever any of its sessions is already known, i.e. "the tab where herdr is running": herdr's cards describe it better. Dropping per-workspace rather than per-session keeps the agent list and the workspace list cut on the same line, or a card would go empty or start representing someone else's status. Costing nothing when a backend is absent is what makes that default safe — no cmux means no event log to read, no Orca means the daemon-pid check fails before any process is spawned, no herdr means one failed CLI call. Everything above that boundary is backend-agnostic: the `herdr:*` event names, the `HerdrAgent` / `HerdrWorkspace` shapes, and — importantly — **all displayed data** (`last_prompt`, `recap`, `token_usage`, AskUserQuestion options) still comes from `read_session_info()` reading `~/.claude/projects/**/*.jsonl` plus the `~/.myspace/ask/<sid>.json` hook file. A backend supplies only the mapping and the status. That ask file is written by a `PreToolUse` hook and deleted by `PostToolUse`, which does not always run (Esc'd question, killed session) — so `ask_file_pending()` deletes a leftover once the pane has been out of `blocked` for 10 s (grace for herdr's own detection lag), or that session shows 입력 대기 forever. Eight things this forces:
- **`src-tauri/src/herdr.rs` is the dispatcher**, not just the herdr client: `list_agents` / `list_workspaces` / `read_pane_text` and the four action commands check `backend()` and delegate to `crate::cmux::*` / `crate::orca::*`. With more than one on, **actions route by session name** (`route_of`) — cmux- and Orca-built entries always carry `session == cmux::SESSION` ("cmux") / `orca::SESSION` ("orca"), so a screen mixing terminals still sends each card's 이동·전송 to the right place; with exactly one backend on it routes there regardless of the name, so entries saved in an older format still work. A list call keeps whichever side succeeded (`unwrap_or_default` + warn), so turning all three on while using only one tool is fine. **The two list paths must iterate the non-herdr backends in the same order with the same `ws_of` rule** (`other_backends()` is that single list) or the agent list and the workspace list get cut on different lines. The watcher loop is untouched — it reads `backend()` every tick, so switching backends needs no restart. Rust can't read localStorage, so `ClaudeNotifier` pushes the choice via `herdr_set_backend` and Rust persists it to `~/.myspace/backend` (same trick as `watch-disabled`; the loop starts before any window exists). Empty persists as the literal `"none"`, because an empty file is indistinguishable from "never saved" and would resurrect the default. The legacy single-choice value `"both"` migrates to **all three** (it was the old default and meant "everything that existed then"), while a deliberate `"cmux"` stays narrow — `backend_from_str` and `migrateWatchBackend` must keep that rule identical or the panel and the watcher disagree about what is on.
- **프롬프트 전송은 본문과 Enter 를 따로 보낸다 — `herdr pane run` 은 쓰지 않는다.** 그 명령이 pty 에 실제로 쓰는 바이트는 (실측) `줄1\n줄2\n줄3\r` 한 덩어리라, 끝의 `\r` 이 "전송"인지 "붙여넣은 본문의 마지막 개행"인지가 순전히 Claude Code 의 붙여넣기 묶기에 달린다. 본문 쪽으로 먹히면 **여러 줄 프롬프트가 입력창에 글자로만 남고 전송되지 않는다**(payload 가 입력창에 줄바꿈 없이 이어 붙어 쌓인 화면으로 확인). 그래서 `herdr_send_prompt` 는 cmux 경로가 이미 하던 모양대로 `pane send-text` 로 본문만 넣고 `PASTE_ENTER_DELAY`(250ms) 뒤 `pane send-keys enter` 를 친다 — 두 단계 모두 단독으로는 확실히 동작하는 것이 실측으로 확인됐다. **bracketed paste(`ESC[200~ … ESC[201~`)로 감싸는 쪽으로 "개선"하지 말 것**: 이론상 개행이 Enter 로 읽힐 여지를 없애 주지만, 실측에서 그 payload 가 통째로 삼켜져 **글자조차 들어가지 않는** 경우가 나왔고 그건 지금 증상보다 나쁜 실패다. 쉬는 구간이 생기므로 이 커맨드는 `async` + `spawn_blocking` 이다(동기 커맨드는 메인 스레드를 잡는다). 두 호출로 나뉘어 첫 호출만 성공하면 텍스트만 들어간 채 남는데, 그때는 터미널에서 Enter 만 치면 되므로 지우지 않고 오류만 올린다.
- **터미널 뷰(`src/features/terminal/` + `src-tauri/src/pty.rs`)는 화면을 흉내 내지 않는다 — 우리가 만든 PTY 안에서 `herdr session attach` 를 돌리고 그 바이트를 xterm.js 에 흘려보낸다.** 그래서 커서·색·CJK IME·리사이즈가 전부 herdr 와 xterm.js 사이에서 해결되고, 아래 선택지 버튼이 다루지 못하는 폼(권한 프롬프트·모델 선택·Esc 취소)도 여기서는 그냥 된다. 폴링으로 터미널을 흉내 내는 쪽은 택하지 않았다: `pane read` 결과에는 **커서 위치 escape 가 없어**(실측) 캐럿을 그릴 수 없고, 로컬 에코가 없어 한글 조합이 깨진다. 실측으로 확인한 herdr 의 성질 다섯이 이 설계를 정한다. (1) **여러 클라이언트가 동시에 붙고, 나중 클라이언트가 먼저 것을 쫓아내지 않는다** — 바이너리에 `terminal attach taken over` 문자열이 있어 tmux 처럼 빼앗을까 걱정했지만 두 번 붙여도 첫 클라이언트는 그대로였다. (2) **클라이언트마다 자기 크기로 렌더된다** — 하나를 120×40, 다른 하나를 60×20 으로 붙이면 각각 그 크기로 그려진다. tmux 라면 세션이 가장 작은 클라이언트로 줄어들어 **앱 안의 좁은 패널이 사용자의 실제 터미널을 망가뜨렸을 것이다.** (3) **반면 "보고 있는 워크스페이스" 는 서버 상태라 공유된다** — `workspace focus` 후 두 클라이언트가 바이트 수까지 같은 프레임을 받는다. 그러니 이 뷰는 "이 카드만 보는 터미널" 이 아니라 herdr 창을 하나 더 띄운 것이고, **뷰가 그 사실을 화면에 적어 둔다**(적지 않으면 터미널이 저절로 움직이는 것이 고장으로 읽힌다). (4) **`HERDR_*` 환경변수가 남아 있으면 `nested herdr is disabled by default` 로 거부된다** — Finder·LaunchAgent 로 뜬 앱에는 없지만 herdr pane 안에서 `bun run tauri dev` 를 돌리면 상속되므로 자식 환경에서 지운다(첫 실험이 이걸로 막혔다). (5) **herdr 전용이다** — cmux 의 `read-screen` 은 도움말에 "as plain text" 라고 적혀 있고 attach 개념이 없으며 Orca 는 Electron IDE 다. 그 판단은 `herdr_attachable_sessions` 가 빈 목록을 주는 것으로 화면에 드러난다(이 커맨드는 조회 실패를 `["default"]` 로 폴백하는 `running_sessions` 와 **규칙이 다르다** — 붙을 수 없는 이름을 보여 주는 것보다 없다고 말하는 편이 정확하다). 세 가지 구현 규칙: PTY 바이트는 **base64 로 싣는다**(읽기 경계가 UTF-8 문자 중간에 떨어져 조각마다 문자열로 옮기면 한글이 깨진다), 세션 지정은 **모듈 스토어**(`terminal-target.ts`)로 넘긴다(같은 창에서 같은 localStorage 키를 두 훅이 쓰면 서로의 쓰기를 못 본다 — 이 저장소가 반복해 부딪힌 함정), 그리고 세션 목록의 「앱 터미널에서 열기」는 `herdr_focus_workspace` 가 아니라 **`herdr_select_workspace`** 를 쓴다(호스트 터미널 앱을 최전면으로 끌어오지 않는다 — 트레이 앱에서 가장 하기 싫은 일이다). 검증은 `attaches_and_detaches_on_a_live_session`(`#[ignore]`, `PTY_SESSION=<세션>`)이 살아 있는 세션에 대고 **양방향**을 본다: 프레임이 오는지, 그리고 우리가 쓴 `ctrl+b q` 가 herdr 에 닿아 자식이 스스로 끝나는지. 분리는 그 클라이언트만 떼어 내므로 세션과 사용자의 실제 터미널은 건드리지 않는다.
- **붙는 일 자체는 `TerminalPane`(`terminal-pane.tsx`)이 하고, 전용 뷰와 세션 목록 상세 패널의 「터미널」 탭이 그 하나를 공유한다.** xterm 을 두 곳에서 각자 만들면 IME 우회(`ime.ts`)와 `unicode11` 문자폭 설정 같은 규칙이 두 벌이 되고 한쪽만 고쳐지는데, 그게 이 저장소가 반복해 부딪힌 함정이다. 그래서 오류 배너와 「다시 연결」까지 그 컴포넌트가 소유하고(상세 패널에는 툴바가 없어 상태를 얹을 자리가 없다) 부모는 `onStatus` 로 받은 크기만 툴바에 그린다. 상세 패널 쪽에서 다섯 가지가 따라온다. (1) **기본은 로그이고, 붙는 것은 「터미널」을 직접 누른 뒤부터다** — 위 (3) 때문에 붙는 순간 사용자의 실제 터미널 화면이 그 카드로 따라 옮겨 가므로, 앱을 켜고 목록을 훑는 것만으로 그 일이 벌어지면 안 된다. 같은 이유로 그 모드는 **localStorage 에 저장하지 않는다**(저장하면 앱을 켠 뒤 카드를 처음 누르는 것만으로 옮겨 간다). 한 번 누르면 카드를 바꿔도 유지되고, 탭을 닫으면 다시 로그부터다. (2) **워크스페이스만 바뀔 때는 PTY 를 다시 열지 않는다** — 같은 세션이면 `herdr_select_workspace` 한 번으로 화면이 옮겨 간다. 그 선택을 `prepare` 로 **attach 직전에** 한 번 더 하는 이유는 자식 effect 가 부모보다 먼저 도는 탓이다: 부모 effect 에만 맡기면 첫 프레임이 엉뚱한 워크스페이스라 화면이 한 번 깜빡인다(멱등이라 한 번 겹치는 것은 무해하다). (3) **터미널 모드에서는 로그 폴링·선택 폼 버튼·프롬프트 입력칸을 모두 내리지 않고 아예 내지 않는다** — 같은 화면과 같은 폼이 터미널에 그대로 떠 있는데 둘을 함께 두면 어느 쪽으로 답해야 하는지가 애매해지고, 커서를 대신 옮기는 경로(`herdr_answer_question`)는 사용자가 직접 고를 수 있을 때는 언제나 두 번째로 정확한 방법이다. 그래도 폼 버튼을 지우지는 않는다 — cmux·Orca 카드에는 붙을 수 없어 그쪽의 유일한 앱 안 답변 수단이다. (4) **모드를 바꿀 때 `question` 을 비우고 `stickRef` 를 되돌린다.** 터미널 모드에서는 폴링이 멈춰 `question` 이 그때 값으로 남는데, 로그로 돌아온 순간 이미 답한 폼이 다시 보이고 그 선택지를 누르면 **다음 질문**에 답하게 된다. `stickRef` 가 false 로 남아 있으면 폴링이 갱신 자체를 미뤄 돌아온 로그가 멈춘 것처럼 보인다. (5) **붙을 수 있는지는 `herdr_attachable_sessions` 목록으로 가른다** — 세션 이름이 `"cmux"`/`"orca"` 인지 뷰가 직접 판정하게 하지 않는다(`can_answer` 를 Rust 가 정해 내려보내는 것과 같은 판단). 그 목록은 상세를 열 때마다 다시 읽는다: 세션은 그 사이 뜨거나 끝날 수 있고 탭을 낼지 말지가 거기 달렸다.
- **터미널 뷰의 한글 입력은 조합(composition) 문제가 아니다 — WebKit 은 한글에 조합 이벤트를 아예 쓰지 않는다.** 증상은 "한글" → **"ㅎㄱ"**(음절마다 첫 자모 하나씩). **PTY·herdr 는 결백하다(실측)**: 버릴 수 있는 세션에 PTY 로 붙어 "한글" 의 UTF-8 바이트를 한 번에 / 글자별 / **바이트별로 쪼개서** 써 봤을 때 세 경우 모두 pane 에 "한글" 이 정확히 들어갔다. 앱에 계측을 넣어 WKWebView 에서 실제로 찍어 보니 `compositionstart`·`compositionupdate`·`compositionend` 가 **한 번도 오지 않고** `isComposing` 도 항상 `false` 였다. 대신 `input` 이벤트로 오는데, **첫 자모는 `insertText`, 그 뒤 다듬어지는 음절은 매번 `insertReplacementText`** 다(`insertText "ㅎ"` → `insertReplacementText "하"` → `"한"` → `insertText "ㄱ"` → `"그"` → `"글"`). xterm 의 `_inputEvent` 는 `inputType === 'insertText'` 만 처리하고 다른 타입은 조건에서 아예 빠지므로, 첫 자모만 나가고 다듬은 결과가 전부 버려진다. 그래서 고치는 지점은 **`insertReplacementText` 하나**다(`ime.ts` 의 `ImeInput`): 받으면 직전에 보낸 조각을 지우고(`DEL` × 길이) 새 값을 보내, 원격 화면이 ㅎ → 하 → 한 으로 따라 바뀌게 한다. `insertText` 는 **손대지 않는다** — xterm 이 이미 그걸로 첫 자모를 보내고 일반 타이핑·이모지도 같은 타입이라, 끼어들면 이중 전송이 된다(일반 키는 xterm 이 `keydown` 에서 보내고 `input` 은 `_keyDownSeen` 가드로 걸러지는데, 한글은 `input` 이 keydown 보다 **먼저** 와서 그 가드가 열린다). ⚠️ **`CompositionHelper` 를 손보는 방향으로 고치려 들지 말 것.** 그 코드는 `textarea.value` 를 잘라 확정 문자열을 만드는 정교한 장치라 범인처럼 보이지만 **여기서는 아예 실행되지 않는다** — 실제로 그 가정으로 한 번 고쳤다가 실기기에서 전혀 듣지 않았다. 그때 하네스가 합성한 조합 이벤트 순서로도 증상("ㅎㄱ")이 똑같이 재현됐다는 점이 교훈이다: **같은 증상을 만드는 순서는 여럿이고, 재현은 원인 규명이 아니다.** 그래서 지금 `./bin/ime-harness.sh` 가 재생하는 순서는 상상이 아니라 **계측 로그에서 그대로 옮긴 실측 순서**이고, 두 줄을 확인한다 — 수정 없음 **`"ㅎㄱ"`**(= 재현) / 수정 적용 `"한글"`. 첫 줄이 `"ㅎㄱ"` 이 아니게 되면 재현 조건이 바뀐 것이므로 수정을 지우기 전에 그것부터 확인할 것. 같은 사내 저장소의 `spectra-jira-ai/chrome_extension` 이 같은 xterm 6 으로 tmux 를 붙이면서 IME 코드가 한 줄도 없는 것은 **반례가 아니다** — Chrome 확장이라 Blink 에서 돌고, Blink 는 조합 이벤트를 정상적으로 준다. 그쪽에서 가져올 것은 IME 가 아니라 `@xterm/addon-unicode11` 이었다: 한글·CJK 는 두 칸을 차지하는데 xterm 의 기본 문자폭 표가 오래된 유니코드 버전이라 herdr 의 판단과 어긋나면 줄이 밀린다. 애드온을 올리는 것만으로는 안 되고 `term.unicode.activeVersion = "11"` 까지 지정해야 새 표가 쓰인다.
- **선택 폼은 세션 목록 상세 패널에서 바로 답한다 — 방향키로 커서를 옮기고, 옮겼는지 화면으로 확인한 뒤에만 Enter 를 친다.** 예전에는 질문을 알려 주기만 하고 선택은 터미널에서 하게 했는데(지워진 `widget-question.tsx` 의 "답변은 하지 않는다"), 트레이 앱에서 그건 알림을 받을 때마다 터미널을 앞으로 끌어와야 한다는 뜻이다. 이제 `herdr_answer_question(session, pane_id, numbers)` 가 그 일을 한다. 다섯 가지가 이 모양을 정한다. (1) **번호키(`1`/`2`)로 곧바로 고르지 않는다.** 그 프롬프트가 번호 단축키를 받는지는 Claude Code 폼 구현에 달렸고, 받지 않으면 숫자는 조용히 무시된 뒤 이어지는 Enter 가 **커서가 있던 엉뚱한 선택지**를 확정한다. 방향키 경로는 매 단계 화면을 다시 읽어 확인할 수 있고, 확인되지 않으면 Enter 를 치지 않고 그만둔다 — 잘못 고르는 것보다 못 고르는 편이 낫다. (2) **키는 한 번에 하나씩 보낸다.** `pane send-keys <pane> up up up` 은 실측에서 셋 중 **하나만** 먹혔고(4번 → 3번), 둘은 먹히기도 해서 더 나쁘다 — 되는지가 타이밍에 달렸다는 뜻이라 "몇 칸 갔는지"를 계산으로 알 수 없다. `PASTE_ENTER_DELAY` 와 같은 입력 묶기 사정이고, 확정 Enter 앞에도 같은 이유로 한 박자를 둔다. 커서가 연속으로 안 움직이면(`CURSOR_STUCK_LIMIT`) 목록 끝이거나 키가 안 먹는 화면이므로 그만둔다 — 목록은 끝에서 **되감기지 않는다**(실측). (3) **커서를 못 읽었으면 `cursor = 0`(모름)이고, 절대 1 로 대신 채우지 않는다.** `❯` 가 안 보이는데 1번에 있다고 믿으면 첫 클릭이 곧바로 오답을 확정한다. `reports_unknown_cursor_as_zero_not_one` 이 이 계약을 붙든다. (4) **Orca 는 답할 수 없다** — CLI 가 `terminal send --text` 뿐이라 방향키를 보낼 수단이 없다. 그 판단은 Rust 가 내려 `AskQuestion.can_answer` 로 내려보낸다(뷰가 백엔드를 알면 안 된다는 규칙 그대로). 화면을 못 읽어 커서를 확인할 수 없을 때도 거짓이고, 그때 UI 는 버튼 대신 "터미널에서 선택" 만 안내한다 — 눌리는 것처럼 보이는 버튼이 매번 실패하는 것보다 낫다. (5) **화면 표시용 읽기는 워처와 갈라 둔다.** 워처가 부르는 `read_question` 은 후크 파일이 있으면 화면을 읽지 않는다(대기 pane 마다 800ms 틱마다 소켓 호출이 두 배가 된다). 상세 패널만 `read_question_full` 을 써서 후크(정확한 라벨·설명·preview)와 화면(커서, 그리고 TUI 가 목록 뒤에 스스로 붙이는 `Type something.` / `Chat about this` — 후크 파일에는 없다, `is_builtin`)을 합친다. 살아 있는 pane 에 대고 읽기→전송→확인 한 바퀴를 도는 `moves_the_cursor_on_a_live_pane` 은 `#[ignore]` 이고 Enter 를 치지 않는다(`ANSWER_SESSION=<세션> ANSWER_PANE=<pane> cargo test … -- --ignored`).
- **cmux's data source is `~/.cmuxterm/events.jsonl`, not its socket.** The socket refuses us outright — "Access denied - only processes started inside cmux can connect" — and My Space launches from Finder/LaunchAgent. But `cmux-claude-wrapper` injects a hook bundle via `--settings` whenever `claude` runs inside cmux (nothing to install), and every hook lands in that log as `agent.hook.<Event>` carrying `session_id` (`"claude-<uuid>"` — **the uuid is the transcript filename**), `workspace_id`, `cwd`, `phase`, and `_ppid`. `scan_text()` replays the log oldest-first; `status_of()` is the whole status table (`Notification`/`PermissionRequest` → blocked, `Stop` → done, `SubagentStop` ignored for the same reason herdr's integration ignores it — it arrives after the turn already ended).
- **Actions still go through the CLI, so they need a password and the list doesn't.** `focus` / `send` / `read-screen` shell out to `/Applications/cmux.app/Contents/Resources/bin/cmux` with `CMUX_SOCKET_PASSWORD` from `settings.claudeCode.cmuxPassword` (cmux 설정 → Automation, key `automation.socketPassword`). Leaving it blank keeps the list, status, and notifications fully working and breaks only those three — say that wherever the field appears, or it reads as a required value. An `Access denied` sets a 60 s backoff (`DENIED_UNTIL`) because the watcher tries a screen read per pane every 800 ms; `set_socket_password` clears it so a freshly typed password isn't ignored for a minute.
- **`pane_id` must stay `"<workspace>:<pane>"`.** `claude-bridge-view.tsx`'s `paneOf` finds a workspace's pane with `pane_id.startsWith(workspace_id + ":")`, so cmux emits `"<ws uuid>:<surface uuid>"` (`pane_ref`) and `parse_target` splits it back into `--surface`/`--workspace`. Deriving the flag from a fresh snapshot instead would re-parse a 1 MB log per pane per tick.
- **Two staleness guards.** Only the newest `boot_id` is replayed (a restarted cmux dropped every old workspace), and an agent whose `_ppid` is no longer in `ps` is filtered out — a `kill -9`'d Claude never sends `SessionEnd`. If cmux itself isn't running the snapshot is empty rather than showing last session's state.
- **Orca joins two sources on `"<tabId>:<leafId>"`.** Orca (`src-tauri/src/orca.rs`, [onorca.dev](https://www.onorca.dev/docs)) is an agent IDE, not a multiplexer, and it splits the two answers: `~/Library/Application Support/orca/agent-hooks/last-status.json` holds per-pane `providerSession.id` (= the Claude transcript filename), `payload.state` and `payload.agentType`, written tmp+rename on every hook; `orca terminal list --json` holds the live `handle`, `title` and `worktreePath`. The status file's entry key **is** `tabId:leafId`, which `terminal list` hands over as two fields — that's the join. Orca installs its hooks globally in `~/.claude/settings.json`, but `claude-hook.sh` exits immediately without `ORCA_PANE_KEY`, so Claude runs outside Orca never appear. State names map straight across (`working`→working, `waiting`→blocked, `done`→done); that table was read out of Orca's own bundle, not guessed — **don't "simplify" `waiting` away**, it is the entire 입력 대기 path.
- **Orca needs the CLI for the list too, so it is cached and pre-gated.** The status file keeps entries for **7 days** after a pane closes (Orca's `HYDRATE_MAX_AGE_MS`), so the file alone lists last week's work; `terminal list` is the liveness filter (and supplies the action handle) the way cmux uses `_ppid`. But `bin/orca` is a shell wrapper that boots Electron as node — ~140 ms a call, and the watcher lists twice every 800 ms. Hence `TERMS_TTL_MS` (2 s) caching of the roster only — the status file is re-read every time, so working/waiting/done transitions are never delayed — plus `runtime_alive()`, which reads `orca-runtime.json` (the socket/token/pid file Orca writes on start and deletes on exit) and `kill(pid, 0)`s it so a closed Orca spawns nothing at all. **Gating on the daemon pid instead is wrong and was the bug**: `daemon/daemon-v*.pid` outlives the app — the daemon keeps running as `Orca Helper` after you quit Orca, and old version-suffixed pid files stay behind — so with Orca closed the gate passed and the watcher spawned a doomed CLI every time the 2 s cache expired, filling the log with `Could not read Orca runtime metadata … Start the Orca app first.` `orca-runtime.json` is the file the CLI actually needs, so its presence *is* the gate. Failures that slip past it (no CLI, permissions) are logged only when the message changes (`note_fail`), for the same reason. A pane with no status entry is a plain shell, not an agent, and is dropped.
- **Orca's workspace is one pane, and `pane_id` puts the handle last.** A card per pane, not per worktree — grouping by worktree would recreate exactly the cmux problem of several agents collapsing into one card that 이동 can't reach individually. So `workspace_id` is the pane key and `pane_id` is `"<tabId>:<leafId>:<handle>"`: that keeps `paneOf`'s `startsWith(workspace_id + ":")` rule while `rsplit_once(':')` recovers the handle. Handles are **runtime-scoped** (Orca restart invalidates them), which is why they are never stored and `focus_workspace` re-looks-them-up. Unlike cmux there is no password: `terminal switch|send|read` need nothing but a running Orca.

**The detail panel's log pauses when you scroll up — that is deliberate, not a missing refresh.** `read_pane` returns the *last N lines* of the pane, re-read every 2 s and swapped in whole, so following it needs two rules and one is not enough. (1) Auto-scroll only when the user was already at the bottom (`stickRef`, `LOG_STICK_SLACK` = 24 px of slack, or fractional heights silently break it) — pinning `scrollTop = scrollHeight` on every poll is what dragged the view back down every 2 s. (2) While scrolled up, **`setLog` is skipped entirely**: the window slides as new lines arrive, so with a preserved `scrollTop` the line you were reading walks off the screen even with auto-scroll disabled. The freeze needs its own affordance — hence the `맨 아래로` pill, which is both the indicator and the way back (scrolling to the bottom resumes it too); it prefixes `갱신 멈춤 ·` only while the task is `working`, since a finished pane's log isn't changing and saying it is announces a problem that doesn't exist. `stickRef` is a ref *and* `following` is state on purpose: the async poll needs a synchronous read, the pill needs a render. The panel's height is `useResizableHeight` + `ResizeHandleH` (`myspace.claudeDetailHeight`), which is why that `<section>` must **not** carry `overflow-hidden` — the handle floats at `-top-2`, outside the panel, in the parent's `gap-3`.

**Calling Rust:** use `trackedInvoke<T>(command, args)` from `src/lib/tauri.ts` instead of raw `invoke` — it wraps `@tauri-apps/api` and emits debug events. Rust commands are registered in `src-tauri/src/lib.rs` via `invoke_handler(generate_handler![...])`; the scaffold ships a `greet` example. `lib.rs` also installs `tauri-plugin-log` and a custom `external-navigation` plugin that opens `http(s)`/`mailto`/`tel` links in the system browser. The window starts hidden (`visible: false`) and is shown on `PageLoadEvent::Finished`.

**UI conventions (shadcn on @base-ui):** components live in `src/components/ui/`. This build uses `@base-ui/react`, whose prop API differs from Radix — some Radix-era props (`asChild`, `delayDuration` on providers) don't exist; triggers take `render={<X/>}`. Add new components with `bunx shadcn@latest add <name>`. `cn()` (clsx + tailwind-merge) is in `src/lib/utils.ts`. Path alias `@/` → `src/`. Global styles/theme tokens in `src/index.css`. `src/components/ui/sidebar.tsx` is **dead code** — `src/components/shell/` replaced it.

**Slack design rules** — anything added to the UI must match these, or it will look pasted-in. The reference is the *current* Slack desktop app: white panels, wine-coloured selection pill, generous type — over chrome (title bar + rail) painted in the preset's **saturated brand colour** with white text, so the point colour reads immediately at the top and left of the window. (An earlier iteration of this app was styled after VS Code — dense, 13 px, square, shadowless. Those rules are **dead**; if you find their fingerprints — `rounded-[2px]`, 22 px rows, 11 px uppercase micro-labels — they are bugs.)
- `src/index.css` holds two token layers: the shadcn tokens (`--background`, `--primary`, …) as **hex** Slack values, and app-chrome `--ui-*` tokens registered in `@theme inline` so `bg-ui-list-hover`, `text-ui-error`, `bg-ui-mention`, `bg-ui-tab-underline` work as utilities. Never delete a `--ui-*` token — Tailwind silently ignores undefined tokens, so a removed name makes styles vanish with no error. Re-point values instead.
- **The theme preset supplies the chrome colour.** `--ui-chrome` / `--ui-chrome-fg` / `--ui-selection` / `--ui-selection-fg` come from `src/lib/themes.ts` (`ModeSpec.chrome` / `chromeFg` / `selection` / `selectionFg`), and `--ui-titlebar|activitybar|statusbar` alias `var(--ui-chrome)` while `--ui-list-active` aliases `var(--ui-selection)`. So switching preset recolours the title bar, the left rail, the status bar, and the active nav pill together. `-chrome-muted-fg|-hover|-active` are `color-mix()` derivations of `--ui-chrome-fg`, so they follow automatically.
- `html { font-size: 15px }` (Slack's body size) and `body { line-height: 1.46667 }`. **Set text sizes in px**: 18 px bold for view/panel titles (`tracking-[-0.01em]`), 17 px bold for the sidebar workspace name, 15 px semibold for section/panel headers (**never uppercase**), 15 px body, 13 px meta/timestamps, 11 px bold badges. Only 10 px `APP`/`WORKFLOW`-style tags may be uppercase. **Those px literals are re-scaled at the bottom of `index.css`, so keep using px and keep the list there in sync.** 설정 → Appearance → Font Size is one number, `--ui-font-scale` (`src/lib/font-sizes.ts`, injected next to `--ui-font`), and everything else is CSS: `html { font-size }` carries the rem-based spacing/icons, the text-bearing shell dims (`--ui-row-h`, `--ui-tabbar-h`, …) multiply by it, and a `@layer utilities` block at the **end** of `index.css` redefines every `text-[Npx]` utility as `calc(Npx * var(--ui-font-scale))` — it wins on source order, so it must stay last. A new px size that isn't in that block is the one thing that silently refuses to scale. `--ui-titlebar-h` deliberately does **not** scale: the macOS Overlay traffic lights sit at a fixed spot, so a taller bar just misaligns them. CSS `zoom` was the obvious alternative and is wrong here — `use-webview-bounds.ts` derives the native child-webview offset from `window.innerHeight` vs `getBoundingClientRect()`, and zoom desyncs those two.
- Slack is **generous with bold**: titles, people's names, buttons, and the active tab are `font-bold`. Emphasis comes from weight *and* colour.
- Density: sidebar nav rows are `h-(--ui-row-h)` = 28 px as `mx-1.5 px-2 rounded-lg` pills; content rows are `min-h-9` (36 px) `px-3 py-1.5 rounded-lg`; panels use `p-4` (headers `px-4 py-3`), the editor area `p-5`. Separate rows with spacing, not borders.
- Radius is `rounded-lg` (8 px, `--radius: 0.5rem`), `rounded-[10px]` for panels/cards, `rounded-full` for badges, chips, reactions, filter buttons, and date dividers. Avatars are `rounded-lg` rounded squares, not circles. `rounded-none` survives only on full-height panels (sheet/drawer) and joined segments.
- Shadows are back: `shadow-[0_1px_3px_rgba(0,0,0,0.06)]` on cards/panels, `shadow-[0_4px_16px_rgba(0,0,0,0.16)]` on floating overlays, nothing elsewhere. Focus is a 2 px ring: `focus-visible:outline-2 focus-visible:outline-offset-1 focus-visible:outline-solid focus-visible:outline-ring` (`outline-solid` is required — Tailwind v4's base `outline-none` otherwise suppresses it).
- Status colours come from `ui-error` (`#E01E5A`) / `ui-warning` / `ui-success` / `ui-info` — Slack's brand four — never hardcoded palette classes (`text-amber-500`, …). Links are `text-ui-link`; mentions are `bg-ui-mention text-ui-mention-fg` chips, group/keyword highlights `bg-ui-highlight`.
- **Two independent theme axes.** *Presets* (`src/lib/themes.ts`): `slack` (default), `vscode`, `claude`, `intellij`, `discord`, `raycast` — six, in that order — set every colour. *Slack themes* (`src/lib/slack-themes.ts`, key `myspace.slackTheme`, 34 entries in Slack's own four groups) override **only** `--ui-chrome` / `--ui-chrome-fg`, i.e. the title bar, rail, and status bar; `null` means "use the preset's chrome". Their `<style>` must stay *after* the preset's in `<head>` — `:root` and `.dark` have equal specificity, so order decides. `from`/`to` draw the sphere swatch only; `chrome` is the flat colour actually applied, and `chromeFg` was pre-picked as white or `#1D1C1D` by contrast. Presets change **colour only**; structure, density, and type scale above stay fixed. Each supplies a saturated brand chrome (light mode: Slack `#862688`, VS Code `#117BC1`, IntelliJ `#365EB2`, Claude `#C05731`, Discord `#6069E4`, Raycast `#C84E4B`; dark mode one step deeper) with `chromeFg: "#FFFFFF"`, and a brighter tone of the same hue as `selection`. Chrome values are tuned so white text keeps a 4.5:1–8:1 contrast ratio — re-tune, don't eyeball, if you change them. `--ui-badge` and `--ui-list-active-fg` follow `--ui-selection`/`--ui-selection-fg`.
- `src/features/pet/*` (the desktop-pet character) is exempt from all of the above.

## Releasing & auto-update

Distribution target is **macOS Apple Silicon only** (no OS code signing/notarization yet — recipients bypass Gatekeeper on first launch). Auto-update is wired via `tauri-plugin-updater` + GitHub Releases.

**How it works:** `App.tsx` calls `checkForUpdates()` (`src/lib/updater.ts`) once on startup. It reads `latest.json` from the endpoint in `tauri.conf.json` → `plugins.updater.endpoints` (`.../releases/latest/download/latest.json`), compares versions against `tauri.conf.json` `version`, and if newer prompts via a sonner toast → downloads → `relaunch()`. Updater artifacts are signed with a minisign key; the **public** key lives in `tauri.conf.json` `plugins.updater.pubkey`.

**Releasing is one command: `./bin/patch-version.sh`** (`--minor` / `--major` / `--set x.y.z`, `--dry-run` to see the plan). Commit your work first, then run it. It bumps the version, commits, tags, pushes, watches the Actions run, publishes the draft, and then **verifies `latest.json` actually serves the new version** — that last check is the only proof users can update. Flags exist to stop partway (`--no-wait`, `--no-publish`, `--skip-check`) or to widen what the release commit picks up (`--include-dirty`, `--include-untracked`).

What it automates, and why each step is load-bearing:
1. The version lives in **four** files — `src-tauri/tauri.conf.json` (the one the updater compares), `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` (the `my-space` package block — stale here and cargo rewrites it mid-build, dirtying the tree), and `package.json`. The build succeeds when they disagree, so hand-editing goes wrong silently. The script writes all four and re-reads them to confirm.
2. `release.yml` triggers on **`v*` tags only** — pushing a commit to `main` does nothing.
3. `.github/workflows/release.yml` builds `macos-latest` aarch64 via `tauri-action`, signs, and creates a **draft** release with the `.dmg`, `.app.tar.gz`, `.sig`, and `latest.json`.
4. **The draft must be published** (`gh release edit <tag> --draft=false --latest`) — `releases/latest/download/` does not serve drafts. Skipping this is invisible: the endpoint 404s and the app's startup check fails *silently* (`checkForUpdates(silent = true)` shows nothing). This is exactly what happened to `v0.0.1` — CI succeeded and uploaded all four assets to a draft that was never published, so the endpoint has 404'd since.
5. **Untracked new files break CI and nothing local catches it.** A new source file left untracked is absent from the release commit, so the *committed* code that imports it fails to compile — but only on the runner: locally the file exists, so `bun run typecheck` and the script's own pre-check both pass. `v0.0.3` died this way (7× `TS2307` for `features/auth/*`, `cowork-spec/bundled-css`, `gcal/employee-search-palette`). The script therefore **stops** on untracked files rather than warning; `--include-untracked` folds them into the release commit. Related: when you delete a failed tag and re-push it, the old failed Actions run has the *same* `headBranch`, so the run must be matched by `headSha` — matching on tag name alone reports the new build as failed the instant it starts.
6. **`gh` acts as its own logged-in account, which on this machine has only `pull` on the repo** (`gh api repos/rudaks-han/my-space --jq .permissions` → `push: false`), while `git push` uses a different credential from the helper. So pushes and tags work but releases 403, and the draft — created before the tag exists, hence named `untagged-…` — doesn't even appear in `gh release list`. It looks like CI never made a release. `bin/patch-version.sh` falls back to the credential-helper token (`git credential fill` → `GH_TOKEN`) for the publish step; the alternative is publishing from the web UI.

Draft-then-publish is kept deliberately over `releaseDraft: false`: assets upload to the draft and go public in one step, so there's no window where `latest.json` announces a version whose `.app.tar.gz` hasn't finished uploading.

Two things to know about how updates reach users: the updater installs the **`.app.tar.gz`**, not the `.dmg` (the app replaces its own bundle and relaunches — no re-install, no `xattr` dance; that's first-install only), and the check runs **only at app startup**, so a tray-resident app that nobody restarts won't notice a release. Also, CI builds **aarch64 only** — `latest.json` has no `darwin-x86_64` entry, so Intel users never update.

**Required GitHub secrets** (Settings → Secrets and variables → Actions): `TAURI_SIGNING_PRIVATE_KEY` (contents of `~/.tauri/myspace-updater.key`) and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (empty for the current key). ⚠️ The private key is **not** in the repo — losing it breaks the update chain for installed apps.

**Two things break a *local* `bun run tauri build` on this machine, and `bin/install.sh` exists to absorb both.** (1) `createUpdaterArtifacts: true` + a `pubkey` in `tauri.conf.json` means the build **fails at the very end** — after the `.app` is already bundled — with "A public key has been found, but no private key"; `bin/install.sh` exports `TAURI_SIGNING_PRIVATE_KEY` from `~/.tauri/myspace-updater.key` (and `…_PASSWORD=""`, or tauri stops to prompt), falling back to `--config '{"bundle":{"createUpdaterArtifacts":false}}'` when the key is absent. (2) `.dmg` bundling mounts a temp volume at `/Volumes` and copies the app in, and **that write is EPERM on this machine** — not a TCC problem: Ghostty *has* Full Disk Access (`com.mitchellh.ghostty|2` in the system TCC.db) and the same image mounted under `$HOME` is writable, so the block is `/Volumes`-path-based, done by the corporate EndpointSecurity agent (`com.jiran.endprotection` — OfficeKeeper — plus FortiClient; see `systemextensionsctl list`). **No terminal permission fixes that**, so don't send anyone to System Settings again. `bin/install.sh` probes with a 1-second throwaway image and, when blocked, builds `--bundles app` and bakes the `.dmg` itself with `hdiutil makehybrid` + `convert` — that path never mounts anything, and exec bits, symlinks, the `/Applications` drag target, and the adhoc signature all survive (verified). What's lost is only the Finder window dressing (background image, icon positions), which `bundle_dmg.sh` needs a writable mount to set. `hdiutil create -srcfolder` is **not** an alternative — it mounts and copies too, and fails the same way.
